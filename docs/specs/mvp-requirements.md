# Carix MVP Detailed Design

> **계보 주의 (2026-07-19 하이브리드 결정):** 이 문서의 제품 기능 정의는 유효하다.
> 단, 데이터 아키텍처 관련 서술(공개연봉 기반 격차 판정, KOSIS·고용24 2원천 구조,
> §5.3 공개연봉 프리미엄, §7.2 워커 구성)은
> [2026-07-15 파이프라인 재설계](data-architecture.md)의
> 원천 4개·임금통계 기준선·RawIngest 구조로 대체되었다.
> 결정 기록: [기능 분해 명세 §6.1](functional-specification.md).

## 1. 문서 목적

이 문서는 Carix 1차 MVP의 제품 요구사항과 구현 경계를 정의한다. MVP는 개인의
소득·소비 변화와 채용시장의 스킬 수요·공개연봉을 연결해 다음 질문에 답한다.

1. 내 실질 구매력은 장기적으로 좋아지고 있는가?
2. 현재 보유 스킬의 시장 수요는 증가하고 있는가?
3. 향후 12개월 동안 잔류, 연봉협상, 이직 탐색, 스킬 보강 중 무엇을 검토해야 하는가?

결과는 재무·세무·노무 자문이나 연봉 보장이 아니다. 데이터와 사용자 가정을
기반으로 한 의사결정 보조 정보이며, 모든 결과에 근거와 데이터 상태를 표시한다.

## 2. 출시 범위

### 2.1 대상 사용자

- 개발, 데이터, AI 직군의 국내 근로자
- 초대받은 10~30명의 비공개 베타 사용자
- 본인의 연봉 이력, 소비 금액, 경력, 스킬을 직접 입력할 수 있는 사용자

### 2.2 포함 기능

- 초대 기반 이메일 매직링크 로그인
- 중단 후 재개할 수 있는 온보딩
- 연봉·선택적 월 실수령액 이력 관리
- 월 소비 카테고리 금액 및 변경 이력 관리
- 표준 스킬 검색, 사용자 정의 스킬, 사용 이력 관리
- 개인 소비구조 기반 구매력 지수
- 동료집단 채용공고 기반 시장가치 지수
- 규칙 기반 결정 신호와 근거
- 잔류·이직의 12개월 보상 시나리오
- 월별 시장 데이터 집계 및 사용자 지수 스냅샷
- 데이터 최신성, 표본 수, 결측률, 추정 여부 표시
- 계정과 개인 데이터 삭제

### 2.3 제외 기능

- 은행, 카드, 급여 계좌 연동
- 이력서 또는 GitHub 자동 분석
- 생성형 AI 추천과 자연어 보고서 생성
- 자동 입사지원 또는 채용 중개
- 실시간 알림과 이메일 리포트
- 관리자 웹 화면
- 모든 직군을 포괄하는 범용 스킬 분류
- 확정적 연봉 예측과 전문 재무·세무·노무 자문

## 3. 사용자 흐름

### 3.1 초대와 로그인

1. 운영자가 제한된 관리 명령으로 이메일을 초대한다.
2. 사용자는 초대된 이메일로 매직링크를 요청한다.
3. 서버는 이메일 존재 여부와 관계없이 동일한 응답을 반환한다.
4. 초대된 이메일에만 15분 동안 유효한 일회성 링크를 발송한다.
5. 링크 검증 후 세션을 생성하고 미완료 온보딩 또는 대시보드로 이동한다.

### 3.2 온보딩

온보딩은 단계별로 자동 저장하며 사용자가 중단 지점에서 재개할 수 있어야 한다.

1. 프로필: 주 직무, 총 경력, 희망 근무 지역, 고용 형태, 선택적 회사 규모
2. 소득: 현재 세전 연봉, 선택적 월 실수령액, 과거 연봉 이력
3. 소비: 월 카테고리별 지출액
4. 스킬: 표준 스킬 검색 또는 직접 추가, 실무 사용 기간, 마지막 사용일
5. 검토: 사용자 입력, 기본값 대체 항목, 계산 제한 사항 확인

### 3.3 대시보드

첫 화면은 세 가지 결과를 독립적으로 보여준다.

- 구매력 지수와 이전 스냅샷 대비 변화
- 시장가치 지수와 이전 스냅샷 대비 변화
- 결정 신호와 적용된 규칙
- 명목소득과 실질 구매력의 월별 추세
- 보유 스킬별 최근 수요 변화
- 비교 가능한 공개연봉 범위
- 표본 수, 공개연봉 결측률, 데이터 기준일
- 사용자 입력값, 기본값 추정, 표본 부족 상태의 구분

### 3.4 의사결정 분석

사용자는 다음 값을 조정한다.

- 현 직장의 향후 12개월 예상 인상률
- 이직 시 목표 세전 연봉
- 이직에 드는 일회성 비용
- 이직 시 예상 구직 공백 기간 (0~6개월)

서버는 잔류 보상, 이직 보상, 두 시나리오의 차이를 계산한다. 차이는 `추정 기회비용`
또는 `추정 추가보상`으로 표시하며 보장된 손실이나 이익으로 표현하지 않는다.

### 3.5 기록 관리

- 연봉, 소비, 스킬 이력 추가 및 수정
- 월별 지수 스냅샷 조회
- 모든 기기에서 로그아웃
- 계정과 개인 데이터 삭제

## 4. 입력 요구사항

### 4.1 프로필

필수 입력은 주 직무, 총 경력, 희망 근무 지역, 고용 형태다. 회사 규모는 선택
입력이다. 동료집단 표본이 부족하면 회사 규모, 지역, 인접 경력 구간 순으로 조건을
완화한다. 화면에는 실제 적용된 조건과 완화 내역을 표시한다.

### 4.2 소득

- 시장 공개연봉 비교에는 세전 연봉을 필수로 사용한다.
- 구매력 계산에는 월 실수령액이 있으면 이를 우선 사용한다.
- 실수령액이 없으면 세전 소득으로 계산하고 `세전소득 기반 추정`으로 표시한다.
- 모든 변경은 유효 시작일과 함께 이력으로 보존한다.
- 같은 유효 시작일의 소득 이력은 중복 저장할 수 없다.

### 4.3 소비

사용자는 다음 카테고리의 월 지출 금액을 입력한다.

- 주거·공공요금
- 식비
- 교통
- 의료
- 교육·자기계발
- 여가·기타

서버는 금액을 소비 가중치로 변환한다. 입력하지 않은 카테고리는 통계청 전체 가구
평균 소비지출 비중으로 보완하고 `추정`으로 표시한다. 소비 변경도 유효 시작일별
이력으로 보존한다.

### 4.4 스킬

- 표준화된 스킬 사전을 검색해 선택한다.
- 사전에 없는 스킬은 사용자 정의 항목으로 추가할 수 있다.
- 각 스킬은 실무 사용 개월 수와 마지막 사용일을 가진다.
- 자기평가 숙련도는 받지 않는다.
- 같은 사용자가 동일한 정규화 스킬을 중복 등록할 수 없다.

## 5. 지표와 결정 규칙

### 5.1 공통 원칙

- 같은 입력, 데이터 버전, 규칙 버전은 항상 같은 결과를 만든다.
- 계산 결과에 원천 데이터 기준일과 규칙 버전을 저장한다.
- 생성형 AI를 계산이나 추천에 사용하지 않는다.
- 표본이 기준보다 작으면 수치를 만들지 않고 `표본 부족`을 반환한다.
- 데이터 연관성은 관측된 추세로 설명하며 인과관계로 단정하지 않는다.

구체적인 가중치, 최소 표본 수, 경력 구간은 데이터 타당성 검증 후 설정 파일과 규칙
버전으로 관리한다. 초기값을 코드 여러 위치에 하드코딩하지 않는다.

### 5.2 구매력 지수

첫 번째 계산 가능한 기준월을 100으로 둔다.

```text
개인물가 변화율 = Σ(카테고리 CPI 변화율 × 개인 소비 가중치)
개인물가 지수 = 기준월부터 개인물가 변화율을 누적한 지수
소득 지수 = 기준월 소득 대비 현재 소득의 지수
구매력 지수 = 소득 지수 ÷ 개인물가 지수 × 100
```

카테고리 매핑이 없거나 CPI가 누락되어 신뢰 가능한 계산이 불가능하면 구매력 지수를
표시하지 않는다. 일부 소비 카테고리에 기본 가중치를 사용한 경우 추정 범위를 함께
표시한다.

### 5.3 시장가치 지수

동료집단은 사용자의 직무, 경력, 지역, 고용 형태와 선택적 회사 규모로 만든다.

```text
스킬 수요율 = 스킬을 언급한 동료집단 공고 수 ÷ 동료집단 전체 공고 수
스킬 수요 지수 = 최근 3개월 수요율 ÷ 그 이전 12개월(4~15개월 전) 수요율 × 100
사용자 시장가치 지수 = Σ(스킬 수요 지수 × 사용기간·최근사용 가중치)
```

기간 창은 비중첩이다. 비교 기준 12개월은 최근 3개월을 제외한 그 이전
12개월(4~15개월 전)을 사용한다.

- 실무 사용 기간이 길고 최근 사용한 스킬에 더 높은 가중치를 준다.
- 최소 표본 기준을 충족하지 못한 스킬은 계산에서 제외하고 별도로 표시한다.
- 공개연봉 프리미엄은 결측률이 높을 수 있으므로 시장가치 지수와 분리한다.
- 공개연봉은 중앙값과 범위, 표본 수, 결측률을 함께 표시한다.

### 5.4 결정 신호

거짓 정밀도를 피하기 위해 세 번째 숫자 지수를 만들지 않는다. 규칙 엔진은 다음 중
하나의 결정 신호를 반환한다.

- `협상 검토`
- `이직 탐색`
- `현 상태 유지`
- `스킬 보강 우선`
- `데이터 부족`

신호는 구매력 변화, 시장가치 변화, 현재 연봉과 공개연봉의 격차, 데이터 신뢰 상태를
조합한다. 화면에는 신호와 함께 적용된 규칙, 사용한 근거, 제외된 데이터 이유를
표시한다. 규칙 충돌 시 우선순위와 임계값은 버전 관리되는 결정표로 정의한다.

### 5.5 12개월 시나리오

```text
잔류 보상 = 현재 연봉 × (1 + 예상 인상률)
이직 보상 = 목표 연봉 × (12 - 공백 개월) ÷ 12 + 실업급여 추정액 - 이직 비용
추정 보상 차이 = 이직 보상 - 잔류 보상
```

구직 공백 기간과 실업급여는 사용자가 입력한 가정을 기반으로 추정하며, 상세 공식은
[도메인 정의서 §4](domain-logic.md)를 따른다. MVP는 세금,
성과급, 주식보상, 퇴직금을 자동 추정하지 않는다. 해당 항목이 결과에 포함되지
않았음을 명확히 표시한다.

## 6. 데이터 모델

핵심 엔터티는 다음과 같다.

| 영역 | 엔터티 | 핵심 정보 |
| --- | --- | --- |
| 인증 | Account, Invitation, MagicLinkToken, Session | 이메일, 초대 상태, 토큰 해시, 만료·폐기 시각 |
| 사용자 | CareerProfile | 직무, 경력, 지역, 고용 형태, 회사 규모 |
| 소득 | IncomeHistory | 세전 연봉, 선택적 실수령액, 유효 시작일 |
| 소비 | ExpenseHistory, ExpenseItem | 기준월, 카테고리, 월 금액 |
| 스킬 | Skill, SkillAlias, UserSkill | 정규명, 별칭, 사용자 정의 여부, 사용 기간, 마지막 사용일 |
| 외부 데이터 | CpiObservation, JobPosting | 출처, 원문 식별자, 관측값, 수집·기준 시각 |
| 집계 | MarketAggregate | 비교 조건, 기간, 공고 수, 수요율, 연봉 통계, 결측률 |
| 결과 | IndexSnapshot, DecisionResult | 지수, 신호, 근거, 데이터·규칙 버전 |
| 시나리오 | CareerScenario | 입력 가정, 12개월 계산 결과 |

외부 API 응답은 원천 추적에 필요한 식별자와 메타데이터를 보존한 뒤 정규화한다.
개인정보와 공용 시장 데이터는 논리적으로 분리하며, 집계 데이터에는 사용자 이메일을
포함하지 않는다.

## 7. 시스템 설계

### 7.1 기술 스택

- 프런트엔드: Vite, React, TypeScript, React Router Framework Mode
- Node SSR: Node.js 24 LTS, Express, `@react-router/express`
- API: Java 21, Spring Boot, Spring Security
- 데이터베이스: PostgreSQL
- 영속성: Spring Data JPA, 복잡한 집계 쿼리는 Spring `JdbcClient`
- 마이그레이션: Flyway
- 배치: Spring Batch와 별도 워커 프로세스
- 테스트: JUnit 5, Testcontainers, 프런트엔드 단위 테스트, Playwright

Spring Boot와 React Router, Vite의 세부 버전은 구현 시작 시 지원 중인 안정 버전으로
잠그고 저장소에 명시한다. 프런트엔드 상세 설계는
[frontend-design.md](frontend-design.md)를 따른다.

### 7.2 구조

단일 저장소의 모듈형 모놀리스로 시작한다.

```text
React Web (Vite + Node SSR)
    |
Spring Boot API
    |- Auth
    |- Profile / Income / Expense / Skill
    |- Market Data
    |- Index Engine
    |- Decision Engine
    `- Scenario
    |
PostgreSQL
    ^
Spring Batch Worker
    |- KOSIS CPI 수집
    |- 고용24 공고 수집
    |- 스킬 정규화
    |- 월별 시장 집계
    `- 사용자 지수 스냅샷
```

API와 워커는 도메인 모델과 계산 규칙을 공유한다. 외부 API별 어댑터를 도메인과
분리해 응답 스키마 변경을 격리한다. 초기에는 메시지 큐 없이 PostgreSQL의 작업 상태와
Spring Batch 실행 이력으로 처리하며, 실제 처리량과 재시도 요구가 확인된 후 큐 도입을
검토한다.

### 7.3 데이터 처리

```text
외부 원천 응답 -> 검증·정규화 -> 월별 시장 집계 -> 사용자별 계산 -> 스냅샷
```

- 수집·집계·스냅샷 작업은 재실행해도 결과가 중복되지 않아야 한다.
- 월별 정기 실행과 사용자 입력 변경 직후 재계산을 지원한다.
- 입력 변경에 따른 즉시 계산은 최신 성공 집계를 사용한다.
- 모든 결과는 원천 데이터 기준일, 수집 시각, 스키마 버전, 규칙 버전을 가진다.
- 관리자 화면 대신 접근 제한된 초대·재수집 명령을 제공한다.

## 8. 보안과 개인정보

### 8.1 인증

- 매직링크는 15분 후 만료되며 한 번만 사용할 수 있다.
- 원본 토큰은 저장하지 않고 암호학적 해시만 저장한다.
- 요청은 이메일과 IP 기준으로 속도 제한한다.
- 초대되지 않은 주소에도 동일한 요청 응답을 반환해 계정 열거를 방지한다.
- 로그인 이메일은 초대 이메일과 정확히 일치해야 한다.
- 세션 기본 유효기간은 30일이며 개별 로그아웃과 전체 기기 로그아웃을 제공한다.

### 8.2 개인정보 처리

- 모든 통신은 HTTPS를 사용한다.
- 운영 DB는 OCI VM의 PostgreSQL 컨테이너로 운영한다 (배포 구성과 동일 — 관리형 서비스 미사용 확정). 볼륨 암호화, 일일 자동 백업과 복구 절차 검증, 이미지 버전 고정을 함께 운영한다.
- 연봉, 실수령액, 소비 금액을 애플리케이션 로그나 분석 이벤트에 남기지 않는다.
- 작업 전달에는 이메일 대신 내부 사용자 ID를 사용한다.
- MVP 운영 도구에서 사용자별 민감 금액을 조회하지 않는다.
- 계정 삭제 시 프로필, 개인 입력, 스냅샷, 시나리오, 세션을 삭제한다.
- 공용 CPI·채용시장 집계는 개인 데이터와 분리한다.

## 9. 검증과 장애 처리

### 9.1 입력 검증

- 음수 또는 허용 범위를 벗어난 금액을 거부한다.
- 지출 합계가 실수령액을 초과하면 경고하되 저장은 허용한다.
- 미래 시점의 소득·소비·스킬 이력은 허용하지 않는다.
- 중복 유효일 소득과 중복 스킬을 거부한다.
- 저장 실패 시 사용자가 입력한 값을 화면에서 보존한다.

### 9.2 외부 데이터 장애

- 외부 API 장애 시 마지막 성공 데이터를 사용하고 `업데이트 지연`과 기준일을 표시한다.
- 유효기간을 넘긴 데이터는 결정 신호의 신뢰 가능한 근거로 사용하지 않는다.
- CPI가 없으면 구매력 지수를 계산하지 않는다.
- 채용공고 표본이 작으면 조건 완화를 적용하고, 그래도 부족하면 `표본 부족`을 표시한다.
- 일부 스킬만 계산 가능하면 계산된 항목과 제외된 항목을 분리한다.
- 어떤 장애 상황에서도 임의 수치를 생성하지 않는다.

### 9.3 관측 가능성

- API 성공률, 수집 건수, 결측률, 배치 소요시간을 측정한다.
- 로그에는 요청 ID와 오류 코드만 남기고 민감 입력을 제외한다.
- 월별 핵심 작업 실패 시 운영자에게 알린다.
- 배치 재시도와 중복 실행 결과를 확인할 수 있어야 한다.

## 11. MVP 완료 기준

다음 조건을 모두 충족해야 비공개 베타를 시작한다.

1. 초대된 사용자가 매직링크로 로그인할 수 있다.
2. 온보딩을 중단하고 같은 지점에서 재개할 수 있다.
3. 두 지수에 계산 근거와 데이터 기준일이 표시된다.
4. 사용자 입력, 기본값 추정, 표본 부족 상태가 구분된다.
5. 결정 신호와 적용 규칙이 표시된다.
6. 사용자가 12개월 잔류·이직 시나리오를 비교할 수 있다.
7. 월별 스냅샷이 중복 없이 생성되고 이력 그래프에 나타난다.
8. 외부 데이터 지연 상태와 마지막 성공 기준일이 표시된다.
9. 사용자가 계정과 개인 데이터를 삭제할 수 있다.
10. 연봉·실수령액·소비 금액이 로그와 분석 이벤트에 남지 않는다.

## 12. 베타 평가 지표

- 초대 사용자 중 온보딩 완료율 70% 이상
- 온보딩 완료자 중 의사결정 분석 실행률 70% 이상
- 사용자 평가에서 근거를 이해할 수 있다는 응답 70% 이상
- 중대한 개인정보 또는 인증 사고 0건
- 월별 핵심 배치 성공률 95% 이상
- 표본 부족률과 공개연봉 결측률을 별도로 수집해 다음 범위 결정에 사용

## 13. 구현 전 선행 검증

전체 기능 구현 전에 KOSIS와 고용24 데이터 타당성 검증을 수행한다.

- 공식 API의 현재 이용 조건, 호출 제한, 필드, 기준 시점 확인
- CPI 카테고리와 Carix 소비 카테고리의 매핑 가능성 확인
- 개발·데이터·AI 직무 필터의 정확도 확인
- 공고 본문에서 스킬을 재현 가능하게 추출할 수 있는지 확인
- 공개연봉 표본 수와 결측률 측정
- 직무·경력·지역별 최소 표본 기준의 후보값 산출

검증 결과가 부족한 영역은 MVP에서 숨기거나 `표본 부족`으로 제공한다. 데이터가 없는
기능을 추정값으로 채워 출시하지 않는다.
