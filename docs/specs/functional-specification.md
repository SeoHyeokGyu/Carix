# Carix MVP 기능 명세서 (Functional Specification)

| 항목 | 내용 |
| --- | --- |
| 대상 독자 | 프런트엔드·백엔드 구현자, 리뷰어 |
| 상위 문서 | [도메인 정의서](domain-logic.md), [ERD](erd.md) |

## 목적과 범위

이 문서는 Carix MVP의 **제품 요구사항과 기능 명세를 함께** 갖는다. 앞쪽(§1~§8)이
화면·스토리·검증·계산 경계·추적 매트릭스로 **무엇을 어떻게 만드는가**를, 뒤쪽(§9~§15)이
출시 범위·사용자 흐름·입력 요구사항·지표와 결정 규칙·테스트 전략으로 **무엇을 왜
만드는가**를 정의한다.

계산 공식, 결정 규칙표, 스킬 사전, 동료집단 완화 알고리즘은 [도메인 정의서](domain-logic.md),
DB 스키마는 [ERD](erd.md), REST 계약은 [API 규격](api-specification.md)이 갖는다. 문서 간 충돌 시 각 주제의 소관 문서를 따르고,
소관 문서끼리도 내용이 어긋나면 최신 커밋을 우선한다.

## 1. 화면 맵과 라우트

공개 랜딩부터 대시보드·설정까지 MVP 전체 화면과 라우팅 규칙을 정의한다. 렌더링
전략은 [프런트엔드 설계](frontend-design.md), 레이아웃은
[프런트엔드 설계](frontend-design.md)를 따른다.

렌더링 열은 MVP 현행 구성이다 — `/` 만 빌드 시 사전 렌더링하고 나머지는 SPA 셸에서
클라이언트가 렌더링한다(`ssr: false`). 화면별 Node SSR·SSR shell 적용은 MVP 이후로
미뤘다: 보호 화면은 전부 세션을 요구해 SEO 대상이 아니고 진입 가드가 이미 클라이언트에서
동작한다. 결정과 근거, 목표 구성 모두 [프런트엔드 설계 §렌더링 전략](frontend-design.md)에 있다.

`S-04`는 매직링크 토큰 검증 화면이었고 인증 방식 변경으로 폐기했다. 번호는 재사용하지
않는다 — 다른 문서가 옛 번호를 가리킬 때 결번임이 드러나야 한다.

계정 없이 접근할 수 있는 화면은 S-01~S-03 뿐이다. 나머지는 모두 세션을 요구한다.

라우팅 가드 규칙:

- 세션 없이 S-05 이후 접근 → 랜딩(`/`) 리다이렉트. 로그인 화면이 아니다 — 처음 온 사용자는
  가입이 필요하고, 랜딩이 가입·로그인을 모두 안내한다
- 온보딩 미완료 세션이 `/dashboard`, `/dashboard/trends`, `/dashboard/skills`, `/dashboard/simulator` 접근 → 마지막 미완료 온보딩 단계로 리다이렉트
- 온보딩 완료 세션이 `/onboarding/*` 접근 → `/dashboard` 리다이렉트 (단, 검토 화면 S-09는 재진입 허용). 검토 화면(S-09) 및 마이페이지 설정(S-13)에서 '온보딩 처음부터 다시 시작'을 실행하면 단계를 `PROFILE`로 초기화하여 1단계부터 온보딩 전 과정을 재수행할 수 있다
- 온보딩 미완료 세션이 `/onboarding/*` 내에서 현재 진행 단계보다 앞선(아직 도달하지 않은) 단계에
  접근 → 현재 단계로 리다이렉트. **현재 단계와 같거나 그 이전 단계 접근은 허용한다** — 검토
  화면(S-09)의 `수정` 링크가 각 항목의 앞선 단계로 되돌아가야 동작하고, 같은 이유로 각 화면의
  `이전` 링크도 필요하다. 알려진 온보딩 경로가 아니면(오타 등) 현재 단계로 되돌린다

## 2. 기능별 사용자 스토리와 인수 조건

형식: `US-<영역>.<번호>`. 인수 조건은 Given / When / Then.

### 2.1 시작과 계정 (AUTH)

**US-A1. 회원가입**
> 처음 온 사람으로서, 이메일과 비밀번호만으로 바로 계정을 만들고 싶다.

- Given 세션 없는 방문자 / When S-03에서 이메일·비밀번호 제출 / Then 계정과 세션(30일)을 만들고 `/onboarding/profile`로 이동한다.
- Given 이미 쓰이는 이메일 / When 제출 / Then `이미 사용 중인 이메일입니다`를 표시한다. 여기서는 존재 여부를 숨기지 않는다 — 숨기면 사용자가 가입 실패 원인을 알 수 없다.
- Given 8자 미만 비밀번호 / When 제출 / Then 길이 오류를 표시한다. 문자 구성은 강제하지 않는다.
- Given 같은 IP에서 연속 요청 / When 제한(IP당 20회/시간) 초과 / Then 만들지 않고 잠시 후 다시 시도하라고 안내한다.

**US-A2. 로그인**
> 계정이 있는 사용자로서, 다른 기기나 세션 만료 후에도 이어서 쓰고 싶다.

- Given 등록된 이메일·비밀번호 / When S-02에서 제출 / Then 새 세션(30일)을 만들고 온보딩 미완료면 마지막 단계로, 완료면 `/dashboard`로 이동한다.
- Given 없는 이메일 또는 틀린 비밀번호 / When 제출 / Then 어느 쪽인지 구분하지 않고 같은 오류를 표시한다 (계정 열거 방지).
- Given 연속 실패 / When 제한(이메일당 10회/시간, IP당 30회/시간) 초과 / Then 잠시 후 다시 시도하라고 안내한다.
- 비밀번호 재설정은 제공하지 않는다. 메일 발송 경로가 없기 때문이다.

### 2.2 온보딩 (ONBD)

**US-O1. 단계별 자동 저장과 재개**
> 사용자로서, 온보딩을 중단해도 입력한 내용이 남아 이어서 진행하고 싶다.

- Given 단계 입력 중 / When 필드 값 변경 후 2초 경과 또는 단계 이동 / Then 서버에 자동 저장되고 `자동 저장됨` 상태가 표시된다. 단, 원자 단위 저장이 필요한 입력(소득: 금액+유효일, 스킬: 스킬+기간+사용일)은 필수 조합이 완비된 시점에 저장하고, 그 전에는 화면 상태로만 유지한다.
- Given 온보딩 중단 후 재로그인 / When 진입 / Then 마지막 미완료 단계에서 기존 입력이 채워진 상태로 재개된다.
- Given 저장 API 실패 / When 재시도에도 실패 / Then 입력값을 화면에 보존하고 오류 배너를 표시한다. 입력을 초기화하지 않는다.

**US-O2. 프로필 입력 (S-05)**

- Given 프로필 단계 / When 주 직무, 총 경력, 희망 지역, 고용 형태 입력 / Then 다음 단계로 진행할 수 있다. 회사 규모는 건너뛸 수 있다.
- Given 필수값 누락 / When 다음 시도 / Then 누락 필드에 인라인 오류를 표시하고 이동을 막는다.

**US-O3. 소득 입력 (S-06)**

- Given 소득 단계 / When 세전 연봉과 연봉 적용 시작일이 모두 완비 / Then `POST /income`으로 이력 1건이 생성된다. 이후 같은 항목의 수정은 `PUT /income/{id}`를 사용한다 (반복 POST 금지 — 유효일 유니크 충돌). 월 실수령액은 선택 입력이다.
- Given 금액 입력 / When 연봉 및 실수령액 입력 / Then 사용자 편의를 위해 '만원' 단위로 입력받고 천 단위 콤마(`,`) 실시간 서식과 실시간 원화 환산 힌트(`= N원`)를 표시하며, 서버 제출 시 원 단위로 환산 전송한다.
- Given 그 사용자의 **첫 소득 행** / When 저장 / Then 변경 사유(`changeReason`)를 `INITIAL` 로 서버가 확정한다. 사용자에게 묻지 않는다.
- Given 두 번째 이후 소득 행 / When 저장 / Then `연봉 인상`(`RAISE`)·`이직`(`JOB_CHANGE`) 중 선택을 받는다. **건너뛸 수 있고 그때는 `null` 로 둔다** — 기본값을 채우면 고르지 않은 것이 고른 것으로 기록된다.
- Given 실수령액 미입력 / When 저장 / Then `구매력 계산은 세전소득 기반 추정으로 표시됩니다` 안내를 노출한다.
- Given 과거 연봉 이력 추가 / When 같은 연봉 적용 시작일 중복 / Then 저장을 거부하고 기존 항목 수정을 안내한다.

**US-O4. 소비 입력 (S-07)**

- Given 소비 단계 / When 6개 카테고리 중 일부만 금액 입력 / Then 저장은 허용하고, 미입력 카테고리는 카테고리 단위 `통계청 평균 기준`(`DEFAULT_CPI`)으로 보완하며 해당 월 요약 상태는 `일부 추정 포함`(`PARTIALLY_ESTIMATED`)으로 안내한다.
- Given 금액 입력 / When 합계가 실수령액(입력된 경우) 초과 / Then 경고를 표시하되 저장은 허용한다.

**US-O5. 스킬 입력 (S-08)**

- Given 스킬 단계 / When 검색어 입력 / Then 표준 스킬 사전에서 별칭 포함 자동완성 결과를 보여준다.
- Given 사전에 없는 스킬 / When 직접 추가 / Then 사용자 정의 스킬로 저장하고 `시장 수요 통계가 제공되지 않을 수 있습니다`를 안내한다.
- Given 스킬 선택 / When 실무 사용 개월 수와 마지막 사용일 입력 / Then 항목이 추가된다. 동일 정규화 스킬 중복 추가는 거부한다.
- Given 스킬 0개 / When 다음 시도 / Then 최소 1개 입력을 요구한다.

**US-O6. 검토와 완료 (S-09)**

- Given 검토 단계 / When 진입 / Then 입력 요약, 기본값으로 대체된 항목 목록, 계산 제한 사항(추정 라벨 예정 항목)을 표시한다.
- Given 기본값으로 대체된 소비 카테고리 / When 검토 화면 표시 / Then 그 카테고리에 **실제로 적용된 금액**을 함께 보여준다(`GET /expenses/applied`). 목록만으로는 어떤 수치로 지수가 계산되는지 알 수 없다. 적용된 금액은 통계청 평균 그 자체가 아니라 사용자 입력 합계로 보간된 값이거나 과거 완전 입력 월에서 전파된 값이다.
- Given 입력도 전파할 과거 월도 없어 절대 금액 기준이 없는 사용자 / When 검토 화면 표시 / Then 금액 대신 **적용된 가중치**를 보여주고 금액 기준이 없다는 사실을 밝힌다. 0원이나 통계청 평균 금액을 임의로 채워 보여주지 않는다.
- Given 소비 입력 화면(`S-07`) / When 카테고리 입력 / Then 평균 금액을 **미리 보여주지 않는다.** 입력 전 노출은 앵커링을 만든다 — 공개는 입력을 마친 검토 단계에서 한다.
- Given 검토 화면 / When 항목별 `수정` 선택 / Then 해당 단계로 이동하고 완료 후 검토로 복귀한다.
- Given 검토 확인 / When 완료 제출 / Then 온보딩 완료 상태가 저장되고 첫 지수 계산이 요청되며 `/dashboard`로 이동한다.
- Given 온보딩 완료 사용자 진입 / When 검토 화면 접근 / Then '온보딩 완료 상태' 알림 배너와 함께 '온보딩 처음부터 다시 시작', '대시보드로 돌아가기' 버튼을 제공한다.

**US-O7. 온보딩 재시작 (Restart / Reset)**
> 사용자로서, 온보딩을 완료한 후에도 초기 설정을 처음부터 다시 검토하고 수정하고 싶다.

- Given 온보딩 완료(`COMPLETED`) 상태 / When 검토 화면(S-09) 또는 마이페이지 설정(S-13)에서 '온보딩 처음부터 다시 시작' 버튼 클릭 / Then `POST /api/v1/auth/onboarding/reset`이 호출되어 사용자 온보딩 단계가 `PROFILE`로 초기화되고 프로필 입력 화면(S-05)으로 이동한다.
- Given 온보딩 재시작 후 화면 진입 / When 각 온보딩 단계(프로필, 소득, 소비, 스킬) 진입 / Then 기존에 등록했던 입력 데이터가 삭제되지 않고 유지된 상태로 인풋에 채워져 있어, 필요한 항목만 수정하고 '다음' 단계로 순차 진행할 수 있다.
- Given 온보딩 완료 상태 / When 대시보드(S-10) 사용 중 / Then 대시보드 상단의 '온보딩 검토 및 재시작' 링크 또는 대시보드 네비게이션의 '설정' 탭을 통해 언제든지 온보딩 재설정 화면으로 접근할 수 있다.

### 2.3 대시보드 (DASH)

**US-D1. 핵심 지표 확인 (S-10)**

- Given 계산 가능한 데이터 / When 대시보드 진입 / Then 구매력 지수, 시장가치 지수, 결정 신호를 이전 스냅샷 대비 변화와 함께 표시한다.
- Given 각 지표 카드 / When 마우스 호버 또는 클릭 / Then 경량 도움말 툴팁(`HelpTooltip`)을 통해 지표 정의 및 100 기준선 판정 가이드(`100 초과`/`100 미만`/`100 기준` 시맨틱 배지 스타일)를 노출한다.
- Given 각 지표 카드 / When 근거 펼치기 / Then 적용된 규칙, 사용 데이터 기준일, 규칙 버전, 제외된 데이터와 이유를 표시한다.
- Given 품목별 CPI 와 사용자 소비 가중치 / When 구매력 지수 카드 표시 / Then 6대 카테고리 중 **그 사용자의 물가 상승에 가장 크게 기여한 1위 품목**을 뱃지로 함께 표시한다(예: `교통비 부담률 최대 상승`). 기여도는 `카테고리 가중치 × 그 품목 CPI 변화`이며, 원자료 CPI 가 아니라 계산된 값이다.
- Given 품목별 CPI 결측 또는 기여도 산출 불가 / When 카드 표시 / Then 뱃지를 표시하지 않는다. 임의 품목을 고르지 않는다.
- Given 소비 가중치 상태 / When 지수 표시 / Then `내 지출 기준`, `일부 추정 포함`, `이전 지출 기준`, `통계청 평균 기준` 중 해당 뱃지를 함께 표시한다 (enum 4종: `USER_DEFINED`/`PARTIALLY_ESTIMATED`/`PROPAGATED`/`DEFAULT_CPI`).
- Given 대시보드 헤더 / When [지표 재계산] 버튼 클릭 / Then `POST /api/v1/dashboard/recalculate`를 비동기 호출하여 최초 유효월부터 현재까지의 스냅샷을 멱등하게 소급 재계산하고 대시보드 지표를 즉시 새로고침한다.
- Given 상단 유틸리티 메뉴 / When '도움말' 클릭 / Then `/dashboard/guide` (S-17) 화면으로 진입하여 상세 산출 공식, 결정 신호 의미, FAQ를 확인한다.
- Given 성과급 수령 기록이 있음 / When 지표 카드 그리드 아래 / Then 「성과급 포함 연간 실소득」 실질 변화율과 최근 12개월 반영 건수를 한 줄로 표시한다. 최근 12개월 소득(고정급 + 성과급)을 직전 12개월 소득과 견주고 12개월 개인물가 상승률로 나눈 값이며, 구매력 지수에는 섞지 않는다. 정의와 산식은 [API 명세 §5.1](api-specification.md) `bonusInclusiveIncome`.
- Given 기준월 포함 24개월 안에 성과급이 없음, 또는 직전 12개월 창을 소득 이력이 온전히 덮지 못함, 또는 개인물가를 비교할 수 없음 / When 대시보드 조회 / Then 이 줄을 표시하지 않는다. 0 이나 추정값으로 채우지 않는다.

**US-D2. 데이터 상태 구분**

- Given 시장가치 표시 / When 비교 조건 노출 / Then 실제 조회 조건(`전국 / 경력 전체 / 회사규모 무관 / 고용형태 무관`)을 서버 문구 그대로 명시한다. 스킬 수요율은 직무 단위로 재므로 경력·지역·규모·고용형태가 비교에 들어가지 않고, 프로필 값으로 조건을 꾸미지 않는다. 규칙은 [도메인 정의서 §2](domain-logic.md).
- Given 표본 수 미달(N < 10) / When 지수 요청 / Then 수치 대신 `표본 부족` 상태와 현재 표본 수를 표시한다. 임의 수치를 만들지 않는다.
- Given 외부 데이터 수집 실패 / When 대시보드 조회 / Then 마지막 성공 데이터 기준으로 표시하고 `업데이트 지연`과 기준일을 노출한다.

**US-D3. 차트 (S-14)**

- Given 12개월 이상 데이터 / When 소득 vs 물가 탭 / Then 소득 지수선(`incomeIndex`)과 개인물가 지수선(`personalPriceIndex`)을 기준월 100 지수 2계열로 표시하고, 소득선이 물가선 아래인 구간에 구매력 손실 음영을 칠한다. 원화 금액은 툴팁 보조 정보로만 노출한다 (원화·지수 축 혼용 금지 — UI §4.1과 동일).
- Given 공개연봉 표본 존재 / When 연봉 분포 탭 / Then 판정 기준선은 공식 임금통계 중앙값이며, 공고 공개연봉 분포(최소·25%·중앙값·75%·최대)는 참고로 병기하고 사용자 위치 핀, 표본 수, 결측률을 함께 표시한다.
- Given 동료집단 공고 10건 이상이고 그중 공개연봉 10건 이상 / When 연봉 분포 탭 / Then 분포·사용자 위치를 낸다. 동료집단 완화는 공고 수와 공개연봉 수가 둘 다 10건을 채우는 단계에 안착하고, 공고만 채우고 공개연봉이 모자라면 한 단계 더 넓힌다. 끝까지 못 채우면 `표본 부족`이며, 공고는 충분한데 공개연봉이 모자라면 「동료집단 공고 N건 중 공개 연봉 M건」을 보인다. 시뮬레이터 실현 가능성도 같은 기준이다.
- Given 경력 구간별 임금 기준선 / When 연봉 분포 탭 / Then 같은 직군의 경력 사다리(`ENTRY`·`JUNIOR`·`MID`·`SENIOR`·`LEAD`)를 구간 카드로 표시하고 사용자 구간을 강조한다. 각 카드에는 해당 구간의 중앙값과 `raiseFromPrevious`(직전 구간 대비 인상률)를 표시한다.
- Given 어느 구간이든 기준선의 `source` 가 `KOSIS` 가 아닌 경우(하드코딩 상수인 `FALLBACK`, 출처 미상인 `UNKNOWN`) / When 사다리 표시 / Then 그 구간을 `추정`으로 라벨링하고 KOSIS 실측 보간 구간과 시각적으로 구분한다.
- Given 동료집단의 무작위 표본 공고 / When 연봉 분포 탭 / Then 「최근 3개월 vs 그 전 3개월」 중앙 제시 연봉을 두 숫자와 판정 한 줄로 병기한다. 현재 분포가 "내가 어디 있나"를 답하고 이 비교가 "시장이 오르는가"를 답한다. 규칙은 §4.6 제시 연봉 추이.
- Given 특정 기간의 공개연봉 표본 부족 / When 비교 표시 / Then 그 기간 수치를 비우고 `표본 부족`과 표본 수를 보인다. 0 이나 인접월 값으로 채우지 않는다.
- Given 두 구간이 겹치거나 표본이 부족해 방향을 말할 수 없음 / When 판정 표시 / Then `상승`·`하락`으로 팔지 않고 `뚜렷한 변화 없음` 또는 `판단 보류`로 말한다.
- Given 월별 결측률 차이 / When 추이 표시 / Then 월별 공개연봉 표본 수와 결측률을 함께 제공한다 — 중앙값 변동이 시장이 아니라 공개 성향 변화일 수 있다.

**US-D4. 스냅샷 이력 (S-11)**

- Given 2개월 이상 스냅샷 / When 이력 화면 진입 / Then 월마다 그 달 끝에 보여 준 판정(당시 판정, 정의는 [도메인 정의서 §5](domain-logic.md))과 지금 규칙으로 다시 계산한 값을 함께 보인다. 결정 신호가 다르면 표시한다. 그 달이 끝난 뒤 계산된 달은 소급 계산으로 구분하고 기본 목록에서 접는다.
- Given 특정 월 선택 / When 상세 보기 / Then 당시 판정과 현재 규칙 값 각각의 근거, 데이터·규칙 버전을 표시한다.
- Given 같은 달에 회차가 2건 이상 / When 회차 비교 / Then 두 회차의 지수·결정 신호 차이와 각 회차의 데이터 버전을 표시하고, 시간 경과가 아니라 입력 변경의 영향임을 문구로 구분한다.
- Given `데이터 부족`이 연속된 달 / When 이력 화면 진입 / Then `rationale`의 적용 규칙에 담긴 사유를 그대로 노출하고 해당 입력을 채우는 화면으로 유도한다.

**US-D6. 스킬 보강 처방 (S-10)**

- Given 결정 신호가 `스킬 보강 우선`(`UPSKILL`) / When 판정 히어로의 처방 블록 표시 / Then 동료집단 공고에서 수요율이 높은 스킬 중 **사용자가 보유하지 않은** 상위 3개를 수요율과 함께 표시한다.
- Given 동료집단 표본이 최소 기준 미달 / When 처방 블록 표시 / Then 목록을 비우고 `표본 부족`을 표시한다. 임의 스킬을 채우지 않는다.
- Given 사용자 정의 스킬(`skill.is_custom`) / When 추천 산출 / Then 후보에서 제외한다. 시장 집계 매칭이 없어 수요율을 만들 수 없다.
- Given 보유 스킬 중 동료집단 표본이 충분한 기준 스킬이 있을 때 / When 추천 근거 표시 / Then **그 스킬과 함께 요구되는 비율**로 근거를 쓴다(예: `보유하신 Spring Boot 공고의 62%가 함께 요구합니다`). 수요율 순위만으로는 왜 그걸 배워야 하는지 말하지 못한다.
- Given 기준 스킬이 없거나 동시출현율이 임계값 미만 / When 근거 표시 / Then 동료집단 수요율 문구로 되돌린다. 낮은 동시출현율을 그대로 쓰면 설득이 아니라 소음이다.
- Given 결정 신호가 `UPSKILL` 이외(`STAY`, `SEEK_JOB`, `NEGOTIATE` 등) / When 판정 히어로 표시 / Then 신호 맥락에 맞춘 라벨(`[이직 대비]`, `[시장 수요]`, `[성장 가이드]`)과 객관적 수요 타이틀로 추천 스킬을 노출한다. 단, 표본 부족 등으로 추천 스킬이 비어있는 경우 불필요한 경고 노출을 방지하기 위해 블록 자체를 숨긴다.
- Given 추천 스킬 후보가 3개를 초과할 때 / When 처방 및 성장 가이드 블록 표시 / Then 3개 단위로 표시하며, 우측 상단에「다른 추천 (현재페이지/전체페이지) 🔄」순환 버튼을 노출하여 사용자가 차순위 수요 스킬(4~6위, 7~9위 등)을 순환 탐색할 수 있도록 지원한다.
- Given 처방 및 추천 블록 표시 / When 하단 안내 링크 클릭 / Then `/dashboard/skills` (`S-18` 스킬 분석) 화면으로 이동하여 보유 스킬 수요 추세와 동료집단 추천 스킬 전체를 확인한다.

**US-D7. 협상 목표 수치 (S-10)**

- Given 결정 신호가 `협상 검토`(`NEGOTIATE`) 또는 `이직 탐색`(`SEEK_JOB`) / When 대시보드 판정 히어로 표시 / Then 규칙 칩 아래에 목표 인상률 셋을 비율로 표시한다 — 공식 임금통계 중앙값까지, 동료집단 공개연봉 75백분위까지, 마지막 연봉 변경 이후 물가 상승분. 원 단위 목표 금액은 표시하지 않는다.
- Given `협상 검토` / When 표시 / Then 블록 제목은 「협상 목표 인상률」이다. Given `이직 탐색` / Then 「희망 연봉 목표」이고 임금통계·p75 줄 라벨은 「~수준」, 복구선 줄은 「~물가 상승분 반영」 꼴이다. 값과 계산은 같다.
- Given 이미 그 목표를 넘어선 항목 / When 표시 / Then 음수 인상률 대신 `이미 상회`로 표시한다. 마지막 연봉 변경 이후 물가가 오르지 않았으면 `물가 상승분 없음`으로 표시한다.
- Given 현재 연봉 미확보 또는 해당 기준선 부재 / When 표시 / Then 그 항목을 `null` 로 두고 화면에서 생략한다. 셋 다 없으면 블록을 숨긴다. 임의 수치를 만들지 않는다.
- Given 그 외 결정 신호 / When 판정 히어로 표시 / Then 이 목록을 표시하지 않는다. 협상 목표는 두 신호에만 붙는다.

**US-D5. 시장 타이밍 확인 (S-10)**

- Given 동료집단 공고 표본 / When 대시보드 진입 / Then 채용 활발도(OWI)를 2층 근거 지표 카드로 구매력·시장가치 지수와 같은 100 기준 축에서 표시한다.
- Given 카드 표시 / When 상세 뱃지 확인 / Then 최근 3개월 동료집단 비중(`최근 비중 X.X%`)과 이전 12개월 동료집단 비중(`이전 비중 Y.Y%`)을 표시한다.
- Given 이전 12개월 표본 미달(또는 수집 이력 15개월 미만)이나 최근 3개월 표본은 기준 이상 / When 지수 요청 / Then 수치 대신 `표본 부족`과 최근 3개월 비중 뱃지만 표시한다. 임의 수치를 만들지 않는다.

**US-D8. 내 상승률 vs 시장 상승률 (S-14)**
> 사용자로서, 내 연봉이 오른 속도가 시장이 오른 속도를 따라갔는지 알고 싶다.

- Given 소득 이력이 두 해 이상 / When 추이분석 `상승률 비교` 탭 진입 / Then 연도별 내 세전 연봉과 동료집단 임금통계 중앙값, 각각의 전년 대비 상승률을 함께 표시한다.
- Given 연속된 두 해가 모두 공식 임금통계 실측(`source = KOSIS`) / When 상승률 표시 / Then 그 구간의 누적 격차를 직전 구간에 이어 쌓는다.
- Given 구간의 어느 한 해라도 실측이 아님(`FALLBACK`·`UNKNOWN`) / When 상승률 표시 / Then **그 구간은 상승률을 내지 않고** 누적 격차는 다음 실측 구간에서 다시 시작한다. 0% 로 채우지 않는다.
- Given 모든 구간이 제외됨 / When 탭 진입 / Then 빈 상태와 `공식 임금통계 결측 구간` 문구를 표시하고 차트를 그리지 않는다.
- Given 임금통계 기준선 표시 / When 어느 화면이든 / Then 그 기준선의 성격(`basis`)과 출처(`source`)를 함께 보여준다.

**US-D9. 스킬 분석 (S-18)**
> 사용자로서, 보유한 스킬의 시장 수요 변화와 동료집단에서 요구되는 미보유 스킬을 한 화면에서 비교하고 싶다.

- Given 온보딩 완료 세션 / When 상단 주 메뉴 `스킬 분석`, 대시보드(`S-10`) 시장가치 지수 카드의 `자세히 보기`, 또는 1층 처방/추천 블록의 `스킬 분석 전체 보기` 클릭 / Then 상단 우측에 `보유 스킬 관리`(`S-12` 스킬 탭) 이동 링크를 두고, **보유 스킬 수요**(`GET /dashboard/skills`) 섹션과 **동료집단 추천 스킬**(`GET /skills/recommendations`) 섹션을 한 화면에 표시한다.
- Given 보유 스킬 수요 섹션 / When 표시 / Then 보유 스킬별 가중치, 최근 3개월 수요 추세(지수 및 상태 뱃지), 원천별 표본·지수 상세 아코디언, 커버리지 뱃지를 표시한다. 등록된 보유 스킬이 없으면 빈 상태를 안내한다.
- Given 동료집단 추천 스킬 섹션 / When 표시 / Then 결정 신호와 무관하게 동료집단 적용 조건(`appliedConditions`)과 미보유 추천 스킬 전체 목록(스킬명, 카테고리, 수요율, 추세 뱃지, 동시출현·수요율 근거 문구)을 표시한다. 동료집단 표본 부족 등으로 추천 목록이 비어 있으면 `표본 부족` 안내를 표시한다.
- Given 두 조회(`GET /dashboard/skills`, `GET /skills/recommendations`) 중 하나만 실패 / When 화면 표시 / Then 성공한 섹션은 그대로 표시하고 실패한 섹션 자리에서만 `다시 시도` 버튼을 제공하며, 둘 다 실패하고 이전 데이터도 없으면 화면 단위 오류 상태를 표시한다.

### 2.4 12개월 시나리오 (SCEN)

**US-S1. 잔류 vs 이직 비교 (S-15)**

- Given 시뮬레이터 화면 (S-15) / When 예상 인상률, 이직 목표 연봉, 이직 일회성 비용, 예상 공백 기간, 실업급여 수급 요건 충족 여부(`isEligibleForUnemploymentBenefit`) 입력 / Then 잔류 보상, 이직 보상(요건 충족 시 실업급여 반영, 미충족 시 급여 0), 차이를 계산해 표시한다.
- Given 계산 결과 / When 표시 / Then 차이를 `추정 추가보상` 또는 `추정 기회비용`으로 라벨링하고, 세금·성과급·주식보상·퇴직금이 미반영임을 문구로 명시한다.
- Given 입력값 변경 / When 재계산 / Then 이전 결과를 덮어쓰기 전 로딩 상태를 표시하고 완료 후 갱신한다.
- Given 시나리오 저장 / When 계산 완료 / Then 입력 가정과 결과를 `CareerScenario`로 보존해 재방문 시 마지막 시나리오를 복원한다.
- Given 저장된 시나리오가 2건 이상 / When 시뮬레이터 진입 / Then 이름 목록을 선택 컨트롤로 제공하고, 고르면 그 입력 가정으로 폼을 채운다(`GET /scenarios`). **비교표는 만들지 않는다** — 목록은 복원용이다.
- Given 저장된 시나리오가 1건 이하 / When 진입 / Then 선택 컨트롤을 감춘다.
- Given 이름 없이 저장된 시나리오 / When 목록 표시 / Then 계산 시각으로 라벨을 만든다.

### 2.5 입력 관리 (REC)

**US-R1. 소득·소비·스킬 이력 CRUD (S-12)**

- Given 이력 화면 / When 연봉 이력 추가·수정 / Then 유효 시작일 기준으로 반영되고 지수 재계산이 요청된다.
- Given 연봉 이력 추가·수정 / When 소득 탭 / Then 변경 사유(`연봉 인상`/`이직`)를 선택할 수 있다. 미선택을 허용한다. 이 값이 12개월 뒤 시나리오 예측을 실제 소득과 맞댈 때 **잔류·이직 중 어느 예측을 검증할지**를 가른다.
- Given 소비 기록 / When 특정 기준월 수정 / Then 해당 월 이후의 가중치 전파(`PROPAGATED`)가 재계산된다.
- Given 스킬 삭제 / When 확인 / Then 시장가치 지수에서 제외되고 다음 계산부터 반영된다.
- Given 미래 날짜 입력 / When 저장 시도 / Then 거부하고 오류를 표시한다.

### 2.6 사용자 설정 (USER)

**US-C1. 세션 관리 (S-13)**

- Given 로그인 상태 / When 상단 계정 메뉴에서 로그아웃 선택 / Then 현재 세션만 폐기되고 로그인 화면으로 이동한다. 다른 기기의 세션은 유지된다.
- Given 로그인 상태 / When 모든 기기에서 로그아웃 선택 / Then 전체 세션이 폐기되고 로그인 화면으로 이동한다.

**US-C2. 사용자 및 개인 데이터 삭제**

- Given 설정 화면 / When 삭제 요청 / Then 삭제 범위(프로필, 입력 이력(성과급 수령 기록 포함), 스냅샷, 시나리오, 세션, 사용자 행)를 고지하고 확인받는다. 이메일 재입력으로 확인받는다.
- Given 삭제 확인 / When 실행 / Then 개인 데이터를 삭제하고 완료 화면을 표시한다. 공용 시장 집계 데이터는 영향받지 않는다.

### 2.7 관리자 파이프라인 (ADMIN)

**US-M1. 수집/집계 파이프라인 수동 구동 및 상태 모니터링**
> 운영 관리자로서, 원천별 데이터 수집 및 월별 시장 집계 파이프라인을 직접 구동하고 진행 상황을 실시간으로 확인하고 싶다.

- Given 관리자 권한 / When S-16에서 원천별 수집(잡코리아/사람인/점핏/원티드 크롤링, 시드 로드, KOSIS 임금통계, 중복제거, 시장 집계)을 실행 / Then 비동기 작업(`JobExecution`)을 트리거하고 즉시 작업 ID(`jobId`)와 상태(`RUNNING`)를 반환받아 화면에 표시한다.
- Given 진행 중인 작업 / When 상태 폴링 또는 목록 새로고침 / Then 현재 처리 단계, 처리 건수(수집 공고 수, 보간 임금통계 수 등), 소요 시간 및 최종 완료(`COMPLETED`)·실패(`FAILED`) 상태를 조회한다.
- Given S-16 작업 실행 이력 / When 성공한 크롤링 작업 줄의 「이 달 신규 공고 보기」 / Then S-20 공고 탭을 최근 수집순으로, 해당 월(작업 시작 시각의 UTC 월)에 처음 관측된 공고만, 수집 포털의 원천(잡코리아·사람인·원티드, 점핏은 사람인, 전체는 원천 없음)으로 걸러 연다.
- Given S-16 크롤링 원천 선택 / When 「원티드」를 고른다 / Then 원천이 개발 공고 목록 전체를 순회하므로 쪽수·요청 간격 입력은 숨겨지고, 모든 공고 처리에 실패하거나 목록을 하나도 받지 못하면 작업이 `FAILED` 로 끝난다. 과거 공고 표본 백필은 S-16 이 아니라 API `POST /internal/pipeline/backfill` 의 `source`(잡코리아·원티드)로 실행한다([API 명세 §8.15](api-specification.md)).
- Given 파이프라인 콘솔 진입 / When 통계 요약 조회 / Then 원천별 총 공고 수(`rawCount`), 정제 공고 수(`cleanedCount`), 중복 제거 공고 수(`dedupedCount`), 임금통계 관측치 수(`totalWageStats`)를 요약 카드로 확인한다.

**US-M2. 데이터 상태 점검**
> 운영 관리자로서, 매달 운영 뒤 사용자 세 질문(구매력·시장가치·결정 신호)에 온전히 답하는지와 고칠 곳을 DB 를 조회하지 않고 알고 싶다.

- Given 관리자 권한 / When S-20 진입 / Then 맨 위 점검 줄이 「답하는 사용자 X/N」, 기준월, 확인 시각(서울)과 점검 5개(재집계 누락·규칙 버전·스냅샷 최신성·CPI 최신월·정기 수집 최신성)의 판정(`OK`·`WARN`·`ERROR`·`UNKNOWN`)을 보인다. 판정할 데이터가 없으면 정상이 아니라 판정 불가(회색)다.
- Given 점검 줄 / When 전부 정상이다 / Then 한 줄로 접힌다. 문제(`WARN`·`ERROR`·`UNKNOWN`)가 있으면 그 점검만 펼쳐 메시지·영향 사용자 수와 「근거」(같은 화면의 해당 탭·기간)·「조치」(S-16) 링크를 보이고 나머지는 「외 N개 정상」으로 줄인다.
- Given 점검 줄 / When 점검을 불러오지 못한다 / Then 실패 문구와 「다시 점검」을 보이고 아래 탭은 그대로 쓴다. 관리자 키가 거부되면(403) 키 입력창을 열고, 키를 저장하면 다시 점검한다. 자동 새로고침은 없다.

**US-M3. 수집 데이터 열람**
> 운영 관리자로서, 판정의 근거와 시장 흐름을 원본 데이터로 확인하고 싶다.

- Given 관리자 권한 / When S-20 월별 현황 / Then 원천별 2단 머리글 아래 월별 잡코리아·원티드 표본, 상한 적용 표본, 정기 수집 건수와 직무별 표본(잡코리아·원티드 중 고른 표본 원천)을 보고, 상한 적용 표본 200 미만·직무 표본 10 미만 칸이 강조된다. 수집 중인 당월 행은 「수집 중」으로 표시하고 강조하지 않으며, 범례가 강조 기준을 설명한다. 기본은 최근 18개월이고 시작·끝 월 입력으로 바꾼다(최대 36개월). 네 탭은 같은 폭·같은 순서(조회 조건 → 범례·건수 줄 → 표)로 그리고, 탭을 바꾸면 기간(`from`·`to`)만 남기고 나머지 조건은 지운다. 불러오기 실패는 어느 탭이든 같은 자리에 「다시 시도」로 보인다.
- Given S-20 공고 / When 월·원천·표본 여부·직무·회사·스킬로 거르고 정렬(최근 수집순 기본, 원천·번호순)을 고른다 / Then 공고 목록과 원천 링크(잡코리아·사람인·원티드)를 본다. 정렬은 URL 쿼리(`sort`)로 유지된다. 제시 연봉은 공개된 금액만 보이고 비공개 검색 구간은 「비공개 (…)」, 급여를 못 읽은 공고는 「판정 전」으로 구분되며 공개 여부로 거를 수 있다. 공고 상세에는 수집 날짜, 확인 경로(수집 경로 목록)와 원천 직군 태그가 보인다. 월을 지정하지 않으면 가장 최근 수집 월을 서버가 골라 월 입력에 채우고, 그 월이 이번 달이면 「수집 중」을 달며, 선택 상자는 고르는 즉시 적용하고, 월·회사·스킬은 Enter 나 포커스 이동으로 적용한다(선택 상자를 고를 때 입력 중이던 월·회사·스킬도 함께 적용). 「조건 초기화」는 공고 조건을 지운다. 월 입력을 비우면 다시 가장 최근 수집 월이 된다. 페이지 이동은 표 위·아래에 둔다. 그 달에 조건에 맞는 공고가 없으면 「이 달에는 조건에 맞는 공고가 없습니다」를 보이고 이번 달이면 「— 표본은 다음 달 백필 뒤 생깁니다」를 덧붙이며, 수집된 공고가 하나도 없으면 「수집된 공고가 없습니다」를 보인다. 원천·직무는 표시명으로 보이고 표본 여부 선택은 「표본·정기 모두」가 기본이며 게시일 열 설명을 툴팁으로 단다.
- Given S-20 CPI·임금통계 / When 탭 진입 / Then CPI 월 × 품목 결측 칸, 임금통계 직무 × 경력 칸별 중위값·출처와 빈 칸이 강조된다. 엔진이 실제로 쓰는 기준선이 최신 연도 값과 다르면(이전 연도 KOSIS 등) 그 값이 함께 강조된다. CPI 열은 분류 이름(A–L)을 함께 보이고, 전월 대비 5% 넘게 변한 칸은 오류가 아니라 중립색 「값 확인」으로 표시하며, 표 위 범례가 급변·결측 표식을 설명한다. CPI 탭도 시작·끝 월 입력이 있고 기간이 없으면 응답 월 범위를 채운다. 임금통계 탭은 기준선이 연령대 기준이며 직무 구분이 없다는 설명 줄을 달고, 경력 구간은 표시명과 근거 연령대(신입 20~24세 … 리드 40~44세)로 보인다. 모든 직무의 값과 엔진 기준선이 같으면 「전 직무 공통」 한 줄로 접고, 하나라도 다르면 직무별 행으로 보인다.
- 공개 원천의 금액(공고 제시 연봉, 임금통계 중위값)은 보이고 사용자 소득은 보이지 않는다. 열람만 하고 데이터를 바꾸지 않는다.

## 4. 계산 경계 규칙

[도메인 정의서](domain-logic.md)의 계산 공식이 다루지 않는
경계·예외 조건을 정의한다.

### 4.1 스킬 수요 지수

```text
스킬 수요 지수 = 최근 3개월 수요율 ÷ 그 이전 12개월(4~15개월 전, 비중첩) 수요율 × 100
```

- **수요율:** 창 안에 신규 수집된(유량) 동료집단 공고 중 그 스킬을 요구하는 공고의 비율이며, 원천마다 그 원천의 측정 프레임 안에서 잰다. 월별 모수와 원천별 프레임의 정의는 [데이터 아키텍처 §1.3](data-architecture.md)이 소관이다.

- **분모 0 (이전 12개월 창(4~15개월 전) 관측 없음):** 그 원천에서는 지수를 계산하지 않고 그 스킬의 원천 결합에서 그 원천만 뺀다(표본 미달과 같은 결합). 모든 원천이 이 상태일 때만 `신규 관측` 으로 시장가치 지수 가중합에서 제외하고 별도 목록에 노출한다 — 이전 창을 과거 표본으로 채운 원천(잡코리아·원티드)과 아직 이력이 쌓이지 않은 원천(점핏 등)이 갈려도 스킬을 버리지 않는다. 이력이 쌓인 원천은 날짜 규칙 없이 저절로 결합에 들어온다.
- **분자 0 (최근 3개월 스킬 관측 없음, 모수는 존재):** 지수 0이 아닌 `최근 수요 없음` 상태로 표시하고 가중합에는 0으로 반영한다.
  - 가중합에 남은 스킬이 전부 이 상태여서 합이 0이 되면 시장가치 지수는 0이 아니라 값 없음(`표본 부족`)이다. 기준 100 지수에서 0은 임의 수치이기 때문이다. 이때 결정 신호는 연봉 격차만으로 내는 부분 판정이고 근거에 `시장가치 미반영` 이 붙는다([도메인 정의서 §6.2](domain-logic.md)) — 제외 스킬 목록이 비어 있어 `시장 집계 미수집 구간`으로 읽히지 않는다.
- **최근 3개월 모수 0 (동료집단 공고 자체가 없음):** 수요율이 정의되지 않으므로 `최근 수요 없음`이 아니라 `집계 없음`으로 표시하고 그 스킬의 원천 결합에서 해당 원천을 뺀다. 모든 원천이 이 상태면 시장가치 지수는 0이 아니라 값 없음(`표본 부족`)이다.
  - `표본 부족`과 갈라 두는 이유는 해소 주체가 다르기 때문이다. 표본 부족은 보유 스킬을 보강하면 달라질 수 있지만, `집계 없음`은 시장 집계가 수집되기 전까지 사용자가 무엇을 입력해도 달라지지 않는다. 이 경우 결정 신호의 근거는 `시장 집계 미수집 구간`이고, 화면은 소득·스킬 입력 유도를 띄우지 않는다.
- **이상치 클램프:** 지수를 [25, 400] 범위로 제한한다. 클램프 적용 시 근거에 `이상치 보정 적용`을 표기한다. (후보값, 데이터 검증 후 확정)

### 4.2 시장가치 지수(MVI)

- 가중치 계산 가능한 스킬이 0개면 MVI를 표시하지 않고 `표본 부족`을 반환한다.
- 사용자 정의 스킬은 시장 집계 매칭이 없으므로 가중합에서 제외하고 `통계 미제공` 상태로 표시한다.
- 제외 스킬의 가중치는 나머지 스킬에 재정규화한다 (총합 1 유지).

### 4.3 구매력 지수(PPI)

- **기준월:** 연봉이 처음 있는 달과 CPI 가 처음 있는 달 중 늦은 달. 기준 소득은 그 달까지 유효한 마지막 연봉이다. 소비 가중치는 기본값이 항상 있다. 기준월 이전 달은 지수를 만들지 않는다.
- **CPI 최신월 결측:** 대상월 CPI 가 아직 없고 마지막 CPI 월이 2개월 이내면 그 달까지 누적한 개인물가로 계산하고, 사용한 CPI 기준월을 스냅샷 근거(`rationale`)의 `cpiAsOf` 에 기록한다(없는 달의 물가를 지어내지 않는다 — 보간하지 않는다). 대시보드는 이 기준월을 따로 표시하지 않는다. 그보다 늦으면 해당 월 지수를 생성하지 않고 마지막 계산월과 `업데이트 지연`을 표시한다.
- **별도 고정상여:** 소득 행이 상여를 따로 받는 것으로 표시돼 있으면(`bonusIncluded = false`) 연 고정상여를 연액/12 로 매달 소득에 더한다. 실수령 경로는 그 행의 실효 수령률로 환산해 더한다. 연봉 0원 행은 상여를 세지 않는다. 성과급은 지수에 섞지 않고(§2.3 대시보드 한 줄이 따로 본다), 스냅샷 근거에 산식 버전을 남긴다. 산식은 [도메인 정의서 §1.3](domain-logic.md) 구매력 지수 산출기.
- **기준월부터 12개월 미만(연봉 이력 1건 포함):** 지수를 계산해 표시하고 `비교 기간 짧음` 을 함께 보인다. 연봉이 그대로면 물가만큼 내려간다.
- **물가 기여도 1위 품목:** `카테고리 가중치 × 그 품목 CPI 변화` 가 가장 큰 카테고리다. 가중치가 `DEFAULT_CPI`(통계청 평균)로 채워진 카테고리도 후보에 포함하되, 그 카테고리가 1위면 화면이 추정 기반임을 함께 표시한다. 전 카테고리 기여도가 0 이하(물가 하락)면 뱃지를 만들지 않는다.

### 4.4 스냅샷 멱등성과 재계산 범위

- 스냅샷 키는 `(user_id, base_year_month, 데이터 버전, 규칙 버전)`. 동일 키 재실행은 기존 행을 대체하며 중복 행을 만들지 않는다.
- 사용자 입력 변경 시 새 데이터 버전을 발급하고, 변경의 가장 이른 유효월부터 현재까지의 스냅샷을 새 버전으로 재계산해 저장한다. 과거 소비 수정에 따른 가중치 전파(US-R1) 재계산도 이 규칙을 따른다.
- **수동 전구간 소급 재계산 (`POST /api/v1/dashboard/recalculate`):** 사용자가 대시보드에서 직접 재계산을 요청하면, 온보딩 최초 유효월부터 현재월까지의 스냅샷을 멱등하게 일괄 재산출한다. 신규 지표(채용 활발도 OWI) 도입이나 계산 알고리즘 변경 시 과거 스냅샷 행에 소급 적용할 수 있는 수단을 제공한다.
- 조회는 월별 최신 `(데이터 버전, 규칙 버전)` 스냅샷을 사용하고, 이전 버전 행은 근거 추적용으로 보존한다.
- 상세 DDL과 대체 의미론은 [도메인 정의서 §5](domain-logic.md)을 따른다.

### 4.5 채용 활발도(OWI)

```text
동료집단 비중 = 동료집단 신규 수집 공고 수 ÷ 전체시장 신규 수집 공고 수
OWI           = 최근 3개월 동료집단 비중 ÷ 이전 12개월(4~15개월 전, 비중첩) 동료집단 비중 × 100
```

- **집계 창:** 시장가치 지수(§4.1)와 같은 창 구조를 쓴다 — 기준월(`baseYearMonth`) 자체는 부분 수집월이므로 제외하고, `[기준월 − 3m, 기준월 − 1m]`(최근 3개월)과 `[기준월 − 15m, 기준월 − 4m]`(이전 12개월)을 비교한다.
- **산출 원천:** `market_aggregate` 의 전체 공고 행(`skill_id IS NULL`)이다. 원천은 시장가치 지수와 같은 4개(`JOBKOREA`·`SARAMIN`·`WANTED`·`JUMPIT`)이며, 동료집단 완화는 경력 축 2단계 사다리(Level 1: 내 경력 구간 — collector 6구간 합산, Level 2: 인접 경력 구간)를 원천별로 독립 적용한다. 전체시장 분모는 직무·경력·지역·고용형태·회사규모가 모두 `ALL` 인 행이다.
- **원천 결합:** 최근·이전 두 창 모두에서 동료집단 표본 수와 전체시장 표본 수가 최소 기준($N \ge 10$) 이상이고 이전 창 비중이 0보다 큰 원천끼리 결합한다. 원천별 지수는 `SourceCombineWeights`(표본 원천은 최근 창 동료집단 표본 수 그대로, 정기 수집 원천은 합계를 표본 원천 최대 표본 수 이하로 비례 축소)로 가중 평균한다.
- **표본 기준:** 결합 가능한 원천이 하나도 없으면(수집 이력 15개월 미만 포함) 지수를 계산하지 않고 `표본 부족`(`INSUFFICIENT_SAMPLE`)을 반환한다. 다만 최근 3개월 창만 기준($N \ge 10$)을 넘긴 원천이 있으면 최근 3개월 비중(`recentSharePercent`)만 산출해 근거에 남긴다.
- **이상치 클램프:** §4.1 과 같은 [25, 400] 범위로 제한한다.
- **`업데이트 지연` 상태를 쓰지 않는다.** CPI·임금통계와 달리 외부 발행 주기에 매이지 않는다.
- **내부 식별자 유지:** 화면 이름은 **채용 활발도**로 표기하되, 코드·DB 컬럼·API 필드 이름은 `OWI`·`opening_window_index`·`openingWindowIndex`·`openingWindow` 를 그대로 유지한다.

### 4.6 제시 연봉 추이

동료집단 중앙 제시 연봉의 **최근·이전 3개월 비교**가 이 절의 본체다. 월별 계열은 그 근거를 보이는 표다. 필드·기간 산식·판정 이름은 [API 명세 §5.2](api-specification.md)가 소유한다.

- **비교 프레임은 무작위 표본이다.** `sampled_month` 가 있는 공고만 세고, 월은 표본이 뽑힌 달로 귀속한다. 두 기간 여섯 달 중 어느 원천에든 표본이 있는 달을 모두 채운 원천만 쓴다. 어느 원천에도 표본이 없는 달은 0건으로 센다. 월 구성이 다른 원천을 섞으면 추세가 아니라 구성 변화를 읽게 된다.
- **끝난 달은 백필 유무로 정한다.** 무작위 표본 백필이 들어온 최신 달(현재 달 이후 값은 깨진 값으로 보고 무시한다)까지가 끝난 달이고, 그 뒤 달은 계산에서 빼고 「집계 중이라 비교에서 제외」로 밝힌다. 날짜 유예로 정하지 않는다. 끝난 달과 원천별 월 커버리지는 공개 연봉이 있는 표본 행만 센다 — 연봉이 없는 표본 행만 앞서 들어온 원천이 끝난 달을 끌어올려 다른 원천을 비우지 않게 한다.
- **방향은 구간이 갈릴 때만 말한다.** 두 기간 중앙값의 95% 신뢰구간(분포 가정 없는 순서통계)이 겹치지 않을 때만 `상승`·`하락`이고, 겹치면 변화 없음, 어느 기간이든 공개연봉이 최소 표본(10건) 미만이면 판단 보류다. 판정이 쉽게 나오면 실패로 본다.
- **결정 신호에 쓰지 않는다.** 판정 기준선은 계속 KOSIS 중앙값이다.
- **월별 표는 전체 수집 공고 기준이다.** 버킷 키는 `job_posting.posted_start_date` 의 등록월이라 수집 회차와 무관하다. 비교와 달리 프레임 필터가 없어 두 숫자가 다를 수 있다.
- **동료집단 완화는 한 번만 돌린다.** 현재 시점 조건으로 한 번 안착시킨 뒤 그 조건으로 월별 집계한다. 월마다 다시 완화하면 달마다 비교 대상이 달라진다.
- **표본 부족은 비운다.** 부족한 달·기간의 중앙값은 `null` 이며 0 이나 인접월 값으로 채우지 않는다.
- **원화 축을 유지한다.** 이 탭은 금액 탭이고, 기준월 100 지수로 바꾸면 [프런트엔드 설계 「소득 vs 물가 추세선」](frontend-design.md)이 금지한 원화·지수 축 혼용이 된다.
- 산출원은 `job_posting` 직접 집계다. `market_aggregate.salary_median` 은 쓰지 않는다 — `base_year_month` 가 집계 실행 라벨이라 등록월을 뜻하지 않는다.

### 4.7 경력 사다리

- **같은 `job_family` 의 경력 구간(`ENTRY`·`JUNIOR`·`MID`·`SENIOR`·`LEAD`, `ALL` 제외)을 표시한다.** `GET /dashboard/salary-distribution` 의 `careerLadder.steps` 는 각 구간의 `wage_stat_observation.wage_median`, 직전 구간 대비 인상률, `source` 를 제공한다. 출처가 다른 점을 한 실측 곡선처럼 연결하지 않고 구간 카드로 나란히 표시한다.
- **`wage_stat_observation` 을 자기 자신과 비교하므로 연령 프록시가 상쇄된다.** 프록시는 모든 구간에 일관되게 걸려 구간 *간* 비율에는 영향이 적다 — 공고 중앙값과 빼는 비교(모수가 다르다)와 다른 점이다.
- **실측이 아닌 적재분은 구간마다 `추정`으로 표시한다.** `source` 가 `KOSIS` 가 아닌 구간 — KOSIS 호출 실패로 `FALLBACK_MEDIAN_BY_BRACKET` 하드코딩 상수가 들어간 `FALLBACK`, 출처 컬럼 도입 이전 적재분인 `UNKNOWN` — 을 실측 보간값과 구분한다. 관측치가 없으면 `median` 과 `raiseFromPrevious` 는 `null`, `source` 는 `UNKNOWN` 이다.
- **사용자 구간 표시는 경력 매핑에 의존한다.** `PeerGroupFallbackResolver.mapExperienceBracket6` 이 `ENTRY`~`LEAD` 구간을 도출하여 신입·12년차 이상이 사다리 양 끝에 정합된다 (개발 계획 §2 `b7`). 사다리는 동료집단 표본이 부족해도 커리어 프로필이 있으면 응답한다.
- 각 구간은 `region = ALL` 관측치를 우선 조회하고 없으면 `전국` 관측치로 대체한다. 어느 경우든 전국 기준이므로 지역 차이를 말하지 않는다.
- `raiseFromPrevious` 는 `(현재 구간 중앙값 - 직전 구간 중앙값) / 직전 구간 중앙값 × 100` 을 소수점 둘째 자리로 반올림한다. 첫 구간이거나 두 중앙값 중 하나가 없거나 직전 중앙값이 0이면 `null` 이다.
- 첫 구간(`ENTRY`)은 이전 구간이 없어 인상률을 내지 않는다.
- **경력 사다리 연도 축 지원 (`US-D8`, 개발 계획 `b14`):** `GET /dashboard/salary-distribution?year=YYYY` 를 통해 특정 기준연도의 경력 사다리를 조회할 수 있다. 미지정 시 최신 기준연도(또는 `baseYearMonth`의 연도)가 적용된다. 응답의 `careerLadder` 는 `basePeriod`(기준 연도) 및 해당 직무의 전체 가용 연도 목록 `availableYears`(오름차순)를 제공하며, 프런트엔드는 가용 연도가 2개 이상일 경우 연도 전환 버튼/탭을 제공해 과거 대비 경력 구간별 임금 구조 추이를 비교 관측할 수 있도록 한다.

### 4.8 협상 목표 인상률

```text
필요 인상률 = (목표 금액 − 현재 세전 연봉) ÷ 현재 세전 연봉
```

- **기준선 셋을 각각 낸다.**
  - **공식 임금통계 중앙값**(`wage_stat_observation`) — 판정 엔진과 같은 해석기로 요청 시점 최신 기준선을 잡는다. 지금 기준선과 스냅샷 판정 때 기준선의 출처가 둘 다 `KOSIS` 일 때만 낸다 — 상수(`FALLBACK`)·출처 불명(`UNKNOWN`) 위의 숫자는 협상 목표로 내밀지 않고, 판정 때 출처가 달랐으면 같은 화면의 출처 표기와 어긋난다. 다시 구한 격차 구간이 스냅샷 판정 때 저장된 구간과 다르면(그 뒤 임금통계가 새로 적재됨) 판정과 모순되므로 이 항목을 `null` 로 둔다.
  - **동료집단 공개연봉 75백분위** — §5.2 `postingReference.p75` 와 같은 값이다. 동료집단 공고 10건과 공개연봉 10건을 둘 다 채우지 못하면 `null` 이다.
  - **구매력 복구선** — 마지막 연봉 변경 이후 개인물가 누적 상승률이다. 그 뒤 연봉이 그대로였으므로 필요 인상률이 곧 상승률이다. 마지막 변경 달 다음 달부터 기준월(CPI 가 늦으면 허용 시차 2개월 안의 마지막 CPI 월)까지, 그 달 소비 가중치로 누적한다(§4.3 과 같은 엔진). 변경이 CPI 수집 전이면 CPI 첫 달부터 세고 그 달을 `sinceYearMonth` 로 밝힌다. CPI 가 2개월 넘게 늦거나 구간 안 카테고리가 빠지면 `null` 이다.
- **이미 목표를 넘었으면 음수가 아니라 `이미 상회` 상태로 돌린다.** 복구선은 상승분이 없으면 `물가 상승분 없음` 상태다. 소수 첫째 자리로 반올림해 0.0 이하면 이 상태로 본다 — 「+0.0%」는 읽히지 않는다.
- **가장 최근 스냅샷 달에만 낸다.** 과거 달은 연봉·CPI 는 그 달인데 임금통계·p75 는 오늘 값이라 시점이 섞인다.
- **금액이 아니라 비율로 돌린다.** 다만 비율을 평문 기준선(`wage_stat_observation` 중앙값·동료집단 공고)과 조인하면 연봉이 원 단위로 복원되므로 **이 값을 `index_snapshot.rationale` 에 저장하지 않고 로그에 남기지 않는다**(§1.3 소득 격차와 같은 경로). 응답은 본인에게만 가므로 무방하지만 저장은 다르다.
- 임금통계 중앙값은 연령대 프록시다([ERD 「스키마 설계 주석」](erd.md)). 화면은 그 기준선의 성격을 함께 표시한다.

### 4.9 임금 상승률 구간

```text
구간 상승률 = (해당 연도 중앙값 − 직전 연도 중앙값) ÷ 직전 연도 중앙값
```

- **구간 단위로 제외한다.** 상승률은 두 점의 차이라 한 점이 실측이 아니면 그 점을 쓰는 구간 둘이 같이 죽는다. 점만 비우는 규율(§4.6 제시 연봉 추이)로는 부족하다.
- **`source = KOSIS` 인 두 점 사이에서만 낸다.** `FALLBACK` 은 하드코딩 상수라 여러 해에 같은 값이 들어가면 상승률 0% 가 되고, 그건 임금이 안 올랐다는 뜻이 아니다. `UNKNOWN` 은 출처 컬럼 도입 이전 적재분이라 어느 쪽인지 모른다.
- **누적 격차는 연속 구간에서만 쌓는다.** 구간이 끊기면 다음 실측 구간에서 0 부터 다시 시작한다.
- **전 구간이 제외되면 빈 상태다.** 0% 를 그리지 않는다.
- 사용자 연봉은 연 단위로 접는다 — 그 해 말일 시점 유효 연봉(`CurrentSalaryProvider.currentGrossSalary(userId, "YYYY12")`)이다. 임금통계가 연 단위 공시라 월 해상도가 없다.
- **이 값을 `index_snapshot.rationale` 에 저장하지 않는다.** 응답은 본인에게만 가므로 무방하나, 저장하면 §4.8 이 막은 금액 복원 경로가 열린다.

## 6. 설계 기준과 미결 항목

### 6.1 설계 계보

제품 기능은 MVP 설계 라인(온보딩 5단계, 이력 관리, 계정 삭제)을, 데이터 아키텍처는
파이프라인 재설계(원천 4개, 임금통계 기준선, RawIngest·dedup, 원천별 집계 후 표본수
가중 결합)를 따른다. **MVP 설계 라인의 문서는 이 문서 §9~§15 로 흡수됐다** — 별도
파일이 아니라 여기가 그 라인의 정본이다.

**인증만 재설계 쪽으로 돌아왔다.** 초대 베타·매직링크 전제를 걷고 이메일·비밀번호
계정으로 바꿨다. 사용자 실체가 본인과 방문자뿐이라 초대 게이트가 지킬 대상이 없었고,
이메일 발송 경로가 없어도 가입·로그인·재로그인이 모두 자기서비스로 돌기 때문이다.

**계보가 갈린 배경:** 파이프라인 재설계가 MVP 설계 전체 대체를
선언했으나, 이후 상세 문서군(API·DB·UI·워크플로우)이 구 MVP 라인을 그대로
따르며 계보가 두 갈래로 분기했다. 재설계는 제품을 포트폴리오·학습용으로 축소(본인+
데모 계정, 매직링크 제거)하고 지수를 개명했으나, 상세 문서군 작업 전부가 초대 베타
제품 라인 기준이었다. 인증에 한해서는 재설계의 판단이 옳았던 것으로 확인돼 그쪽을
채택했다.

**검토한 대안:**

- **A. MVP 설계 라인 전면 유지, 재설계 폐기** — 데이터 리스크(고용24 커버리지, 공개연봉
  결측) 미해결.
- **B. 파이프라인 재설계 전면 채택** — 인증·온보딩·삭제 등 상세 문서군 산출물 대규모 재작업.

둘 다 접고 하이브리드로 정리했다 — 제품은 이미 완성도 높은 MVP 설계 라인을 유지하고,
데이터는 실측으로 드러난 리스크를 해결한 파이프라인 재설계를 채택한다.

문서 간 충돌 시 이 §6.1을 따르고, 그래도 어긋나면 최신 커밋을 우선한다. 리뷰
라운드별 세부 수정 이력은 git 커밋 히스토리를 참조한다.

## 10. 사용자 흐름

### 10.1 가입과 로그인

1. 방문자가 랜딩에서 가입을 눌러 이메일과 비밀번호로 계정을 만든다.
2. 가입 즉시 세션(30일)을 발급하고 온보딩 첫 단계로 보낸다.
3. 이미 계정이 있으면 이메일과 비밀번호로 로그인한다. 온보딩 미완료면 마지막 단계로, 완료면 대시보드로 간다.
4. 세션이 없는 접근은 랜딩으로 보낸다.

이메일 소유 증명과 비밀번호 재설정은 두지 않는다. 메일 발송 경로가 없기 때문이다.

### 10.2 온보딩

온보딩은 단계별로 자동 저장하며 사용자가 중단 지점에서 재개할 수 있어야 한다.

1. 프로필: 주 직무, 총 경력, 희망 근무 지역, 고용 형태, 선택적 회사 규모
2. 소득: 현재 세전 연봉, 선택적 월 실수령액, 과거 연봉 이력
3. 소비: 월 카테고리별 지출액
4. 스킬: 표준 스킬 검색 또는 직접 추가, 실무 사용 기간, 마지막 사용일
5. 검토: 사용자 입력, 기본값 대체 항목, 계산 제한 사항 확인

### 10.3 대시보드

첫 화면은 세 가지 핵심 결과만 독립적으로 보여준다. 상세 추이와 스킬 시장 정보는 별도 하위·분석 화면에서 확인한다.

- 구매력 지수와 이전 스냅샷 대비 변화
- 시장가치 지수와 이전 스냅샷 대비 변화
- 결정 신호와 적용된 규칙
- 사용자 입력값, 기본값 추정, 표본 부족 상태의 구분

지표 카드 아래에는 성과급 수령 기록이 있을 때만 「성과급 포함 연간 실소득」 한 줄을 둔다(US-D1). 기록이 없거나 비교할 수 없으면 줄이 없다.

**추이분석 화면**은 다음을 보여준다.

- 명목소득과 실질 구매력의 월별 추세
- 비교 가능한 공개연봉 범위 및 경력 사다리
- 표본 수, 공개연봉 결측률, 데이터 기준일

**스킬 분석 화면**은 다음을 보여준다.

- 보유 스킬별 가중치, 최근 수요 추세 지수, 원천별 표본·지수 상세
- 동료집단 공고에서 자주 요구하는 미보유 추천 스킬 및 동시출현 근거

### 10.4 의사결정 분석

사용자는 다음 값을 조정한다.

- 현 직장의 향후 12개월 예상 인상률
- 이직 시 목표 세전 연봉
- 이직에 드는 일회성 비용
- 이직 시 예상 구직 공백 기간 (0~6개월)

서버는 잔류 보상, 이직 보상, 두 시나리오의 차이를 계산한다. 차이는 `추정 기회비용`
또는 `추정 추가보상`으로 표시하며 보장된 손실이나 이익으로 표현하지 않는다.

### 10.5 기록 관리

- 연봉, 소비, 스킬 이력 추가 및 수정
- 월별 지수 스냅샷 조회
- 로그아웃(상단 계정 메뉴)·모든 기기에서 로그아웃
- 사용자 정보 및 개인 데이터 삭제

## 11. 입력 요구사항

### 11.1 프로필

필수 입력은 주 직무, 총 경력, 희망 근무 지역, 고용 형태다. 회사 규모와
현 직장 입사일은 선택 입력이다. 입사일은 오늘(서울 기준) 이후 날짜를 받지 않는다. 동료집단 표본이 부족하면 회사 규모, 지역, 인접 경력 구간 순으로 조건을
완화한다. 화면에는 실제 적용된 조건과 완화 내역을 표시한다.

### 11.2 소득

- 시장 공개연봉 비교에는 세전 연봉을 필수로 사용한다.
- 구매력 계산에는 월 실수령액이 있으면 이를 우선 사용한다.
- 실수령액이 없으면 세전 소득으로 계산하고 `세전소득 기반 추정`으로 표시한다.
- 모든 변경은 유효 시작일과 함께 이력으로 보존한다.
- 같은 유효 시작일의 소득 이력은 중복 저장할 수 없다.
- 소득 행마다 연봉 계약 금액에 상여가 들어 있는지(기본 "들어 있음")를 기록한다. "따로 받음"이면 연간 고정상여(0 초과)를 함께 받는다.
- 상여 조건은 사용자가 고른 연봉 행부터 이후 행에 일괄 적용한다. 새 소득 행은 직전 행의 조건을 물려받고, 유효 시작일을 바꿔도 다시 상속하지 않는다. 규격은 [API 명세 §4.3](api-specification.md).
- 성과급 수령 기록은 지급월과 금액 한 쌍이며 같은 달에 여러 건을 기록할 수 있다. 미래 달은 받지 않는다. 규격은 [API 명세 §4.4](api-specification.md).

### 11.3 소비

사용자는 다음 카테고리의 월 지출 금액을 입력한다.

- 주거·공공요금
- 식비
- 교통
- 의료
- 교육·자기계발
- 여가·기타

서버는 금액을 소비 가중치로 변환한다. 입력하지 않은 카테고리는 통계청 전체 가구
평균 소비지출 비중으로 보완하고 `추정`으로 표시한다. 소비 변경도 유효 시작일별
이력으로 보존한다.

### 11.4 스킬

- 표준화된 스킬 사전을 검색해 선택한다.
- 사전에 없는 스킬은 사용자 정의 항목으로 추가할 수 있다.
- 각 스킬은 실무 사용 개월 수와 마지막 사용일을 가진다.
- 자기평가 숙련도는 받지 않는다.
- 같은 사용자가 동일한 정규화 스킬을 중복 등록할 수 없다.

## 12. 지표와 결정 규칙

### 12.1 공통 원칙

- 같은 입력, 데이터 버전, 규칙 버전은 항상 같은 결과를 만든다.
- 계산 결과에 원천 데이터 기준일과 규칙 버전을 저장한다.
- 생성형 AI를 계산이나 추천에 사용하지 않는다.
- 표본이 기준보다 작으면 수치를 만들지 않고 `표본 부족`을 반환한다.
- 데이터 연관성은 관측된 추세로 설명하며 인과관계로 단정하지 않는다.

구체적인 가중치, 최소 표본 수, 경력 구간은 데이터 타당성 검증 후 설정 파일과 규칙
버전으로 관리한다. 초기값을 코드 여러 위치에 하드코딩하지 않는다.

### 12.2 구매력 지수

첫 번째 계산 가능한 기준월을 100으로 둔다.

```text
개인물가 변화율 = Σ(카테고리 CPI 변화율 × 개인 소비 가중치)
개인물가 지수 = 기준월부터 개인물가 변화율을 누적한 지수
소득 지수 = 기준월 소득 대비 현재 소득의 지수
구매력 지수 = 소득 지수 ÷ 개인물가 지수 × 100
```

- 누적은 월별 가중 변화율을 곱한다. 그 달 가중치는 도메인 정의서 §1.1 상속 규칙으로 정한다.
- 기준월~마지막 CPI 월 사이 한 달이라도 6개 카테고리 변화율이 다 있지 않으면 계산하지 않는다. 남은 가중치를 재조정하지 않는다.
- 소득은 기준월·현재월 둘 다 실수령액이 있으면 실수령액, 아니면 둘 다 세전 연봉으로 비교한다.

카테고리 매핑이 없거나 CPI가 누락되어 신뢰 가능한 계산이 불가능하면 구매력 지수를
표시하지 않는다. 일부 소비 카테고리에 기본 가중치를 사용한 경우 추정 범위를 함께
표시한다.

### 12.3 시장가치 지수

스킬 수요율의 동료집단은 사용자의 **직무**로 만든다(경력 전체). 무작위 표본을 경력으로 쪼개면 스킬별 건수가 너무 작아 지수가 잡음에 휘둘린다. 경력은 연봉 기준선(임금통계)에서 가른다. 시장 집계가 지역·고용 형태·회사 규모로 나뉘지 않아 이 셋도 전국·무관 기준이다 — 차원을 늘리는 일은 개발 계획 `b25`, 규칙은 [도메인 정의서 §2](domain-logic.md).

```text
스킬 수요율 = 스킬을 언급한 동료집단 공고 수 ÷ 동료집단 전체 공고 수
스킬 수요 지수 = 최근 3개월 수요율 ÷ 그 이전 12개월(4~15개월 전) 수요율 × 100
사용자 시장가치 지수 = Σ(스킬 수요 지수 × 사용기간·최근사용 가중치)
```

기간 창은 비중첩이다. 비교 기준 12개월은 최근 3개월을 제외한 그 이전
12개월(4~15개월 전)을 사용한다.

- 실무 사용 기간이 길고 최근 사용한 스킬에 더 높은 가중치를 준다.
- 최소 표본 기준을 충족하지 못한 스킬은 계산에서 제외하고 별도로 표시한다.

### 12.4 결정 신호

거짓 정밀도를 피하기 위해 세 번째 숫자 지수를 만들지 않는다. 규칙 엔진은 다음 중
하나의 결정 신호를 반환한다.

- `협상 검토`
- `이직 탐색`
- `현 상태 유지`
- `스킬 보강 우선`
- `데이터 부족`

신호는 구매력 변화, 시장가치 변화, 데이터 신뢰 상태를
조합한다. 화면에는 신호와 함께 적용된 규칙, 사용한 근거, 제외된 데이터 이유를
표시한다. 규칙 충돌 시 우선순위와 임계값은 버전 관리되는 결정표로 정의한다.

### 12.5 12개월 시나리오

```text
잔류 보상 = 현재 연봉 × (1 + 예상 인상률)
이직 보상 = 목표 연봉 × (12 - 공백 개월) ÷ 12 + 실업급여 추정액 - 이직 비용
추정 보상 차이 = 이직 보상 - 잔류 보상
```

구직 공백 기간과 실업급여는 사용자가 입력한 가정을 기반으로 추정하며, 상세 공식은
[도메인 정의서 §4](domain-logic.md)를 따른다. MVP는 세금,
성과급, 주식보상, 퇴직금을 자동 추정하지 않는다. 해당 항목이 결과에 포함되지
않았음을 명확히 표시한다.

## 13. 검증과 장애 처리

### 13.1 외부 데이터 장애

- 외부 API 장애 시 마지막 성공 데이터를 사용하고 `업데이트 지연`과 기준일을 표시한다.
- 유효기간을 넘긴 데이터는 결정 신호의 신뢰 가능한 근거로 사용하지 않는다.
- CPI가 없으면 구매력 지수를 계산하지 않는다.
- 채용공고 표본이 작으면 조건 완화를 적용하고, 그래도 부족하면 `표본 부족`을 표시한다.
- 일부 스킬만 계산 가능하면 계산된 항목과 제외된 항목을 분리한다.
- 어떤 장애 상황에서도 임의 수치를 생성하지 않는다.

### 13.2 관측 가능성

- API 성공률, 수집 건수, 결측률, 파이프라인 소요시간을 측정한다.
- 로그에는 요청 ID와 오류 코드만 남기고 민감 입력을 제외한다.
- 핵심 작업 실패 시 운영자에게 알린다.
- 파이프라인 재시도와 중복 실행 결과를 확인할 수 있어야 한다.

## 14. 테스트 전략

### 14.1 단위 테스트

- 개인물가 및 구매력 지수 계산
- 스킬 수요율 및 시장가치 지수 계산
- 미입력 소비 카테고리 기본 가중치 적용
- 동료집단 조건 완화 순서
- 결정 신호 규칙과 충돌 우선순위
- 12개월 잔류·이직 시나리오
- 비밀번호 해시 검증과 로그인 실패 응답 동일성

### 14.2 통합 테스트

- 소득·소비·스킬 이력 CRUD
- 외부 API 실패 시 마지막 성공 데이터 사용
- 스냅샷과 수집/집계 파이프라인의 멱등성
- 데이터·규칙 버전에 따른 결과 재현
- 사용자 및 개인 데이터 삭제 후 제거

PostgreSQL 동작에 의존하는 테스트는 두지 않는다([DEVELOPMENT.md §6](../DEVELOPMENT.md)). DB 동작은 앱을 OCI DB 에 붙여 직접 확인한다.

### 14.3 E2E 테스트

다음 핵심 경로를 실제 브라우저에서 검증한다.

```text
가입 -> 온보딩 중단·재개 -> 지수 확인
-> 연봉 수정 후 재계산 -> 12개월 시나리오 -> 월별 이력 조회 -> 재로그인
```

### 14.4 데이터 품질 검사

- 전월 대비 수집 건수 급감
- 공개연봉 결측률 급증
- 직무·지역·스킬 코드 매핑 실패
- 중복 공고와 비정상 연봉 값
- 월별 CPI 누락

## 15. 베타 평가 지표

- 가입 사용자 중 온보딩 완료율 70% 이상
- 온보딩 완료자 중 의사결정 분석 실행률 70% 이상
- 사용자 평가에서 근거를 이해할 수 있다는 응답 70% 이상
- 중대한 개인정보 또는 인증 사고 0건
- 월별 핵심 수집/집계 파이프라인 성공률 95% 이상
- 표본 부족률과 공개연봉 결측률을 별도로 수집해 다음 범위 결정에 사용
