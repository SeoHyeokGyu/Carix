| 항목 | 내용 |
| --- | --- |
| 문서 상태 | 채택 (Baselined) |
| 버전 | 1.0 |
| 대상 독자 | 프런트엔드·백엔드 구현자, 리뷰어 |

## 목적과 범위

이 문서는 Carix MVP의 기능 요구사항을 화면과 사용자 스토리 단위로 확정한다. 화면
맵과 라우팅, 기능별 인수 조건(Given/When/Then), 입력 검증 값, 계산 경계 규칙,
화면 상태, 완료 기준 매핑, 화면–스토리–API–데이터 추적 매트릭스를 정의한다.

계산 공식, 결정 규칙표, 스킬 사전, 동료집단 완화 알고리즘, DB 스키마는 상위 문서와
[도메인 정의서](domain-logic.md)·[API 규격](api-specification.md)에서
정의하며, 이 문서는 이를 참조한다. 문서 간 충돌 시 각 주제의 소관 문서를 따르고,
소관 문서끼리도 내용이 어긋나면 최신 커밋을 우선한다.

## 1. 화면 맵과 라우트

공개 랜딩부터 대시보드·설정까지 MVP 전체 화면과 라우팅 규칙을 정의한다. 렌더링
전략은 [프런트엔드 설계](frontend-design.md), 레이아웃은
[UI/UX 설계](ui-ux-design.md)를 따른다.

| # | 라우트 | 화면 | 렌더링 | 접근 조건 |
| --- | --- | --- | --- | --- |
| S-01 | `/` | 랜딩 | 사전 렌더링 | 공개 |
| S-02 | `/login` | 로그인 (이메일·비밀번호) | Node SSR | 공개 |
| S-03 | `/register` | 계정 등록 (익명 → 등록 승격) | SSR shell + hydration | 세션 |
| S-05 | `/onboarding/profile` | 온보딩 1: 프로필 | SSR shell + hydration | 세션 |
| S-06 | `/onboarding/income` | 온보딩 2: 소득 | SSR shell + hydration | 세션 |
| S-07 | `/onboarding/expense` | 온보딩 3: 소비 | SSR shell + hydration | 세션 |
| S-08 | `/onboarding/skills` | 온보딩 4: 스킬 | SSR shell + hydration | 세션 |
| S-09 | `/onboarding/review` | 온보딩 5: 검토 | SSR shell + hydration | 세션 |
| S-10 | `/dashboard` | 대시보드 메인 (핵심 지표 3카드) | SSR shell + hydration | 세션 + 온보딩 완료 |
| S-11 | `/dashboard/history` | 월별 스냅샷 이력 | SSR shell + hydration | 세션 + 온보딩 완료 |
| S-12 | `/mypage/records` | 소득·소비·스킬 이력 관리 | SSR shell + hydration | 세션 |
| S-13 | `/mypage/profile` | 세션·사용자 정보 관리, 삭제 | SSR shell + hydration | 세션 |
| S-14 | `/dashboard/trends` | 추이분석 (소득vs물가·스킬수요·연봉분포) | SSR shell + hydration | 세션 + 온보딩 완료 |
| S-15 | `/dashboard/simulator` | 12개월 시뮬레이터 | SSR shell + hydration | 세션 + 온보딩 완료 |

`S-04`는 매직링크 토큰 검증 화면이었고 인증 방식 변경으로 폐기했다. 번호는 재사용하지
않는다 — 다른 문서가 옛 번호를 가리킬 때 결번임이 드러나야 한다.

`세션`은 익명 세션과 등록 계정 세션을 구분하지 않는다. 익명 사용자도 온보딩·대시보드·
마이페이지를 모두 쓴다.

라우팅 가드 규칙:

- 세션 없이 S-05 이후 접근 → `/login` 리다이렉트
- 온보딩 미완료 세션이 `/dashboard`, `/dashboard/trends`, `/dashboard/simulator` 접근 → 마지막 미완료 온보딩 단계로 리다이렉트
- 온보딩 완료 세션이 `/onboarding/*` 접근 → `/dashboard` 리다이렉트 (검토 화면 S-09는 재진입 허용)

## 2. 기능별 사용자 스토리와 인수 조건

형식: `US-<영역>.<번호>`. 인수 조건은 Given / When / Then.

### 2.1 시작과 계정 (AUTH)

**US-A1. 가입 없이 시작**
> 처음 온 사람으로서, 가입 절차 없이 바로 써 보고 싶다.

- Given 세션 없는 방문자 / When S-01에서 시작 / Then 익명 세션(30일)을 만들고 `/onboarding/profile`로 이동한다. 입력 단계를 거치지 않는다.
- Given 유효한 세션이 이미 있음 / When 다시 시작 / Then 새 세션을 만들지 않고 기존 세션을 유지한다. 입력한 데이터를 잃지 않는다.
- Given 같은 IP에서 연속 요청 / When 제한(IP당 20회/시간) 초과 / Then 발급하지 않고 잠시 후 다시 시도하라고 안내한다.

**US-A2. 계정 등록 (승격)**
> 익명으로 쓰던 사용자로서, 결과를 다른 기기에서도 이어 보고 싶다.

- Given 익명 세션 / When S-03에서 이메일·비밀번호 제출 / Then 같은 사용자 행에 이메일과 비밀번호 해시를 채우고 입력한 데이터를 그대로 유지한다. 세션도 유지한다.
- Given 이미 등록된 계정 / When 등록 시도 / Then `이미 등록된 계정입니다`를 표시한다.
- Given 다른 사용자가 쓰는 이메일 / When 제출 / Then `이미 사용 중인 이메일입니다`를 표시한다. 여기서는 존재 여부를 숨기지 않는다 — 숨기면 사용자가 원인을 알 수 없다.
- Given 8자 미만 비밀번호 / When 제출 / Then 길이 오류를 표시한다. 문자 구성은 강제하지 않는다.

**US-A3. 재로그인**
> 등록한 사용자로서, 다른 기기나 세션 만료 후에도 이어서 쓰고 싶다.

- Given 등록된 이메일·비밀번호 / When S-02에서 제출 / Then 새 세션(30일)을 만들고 온보딩 미완료면 마지막 단계로, 완료면 `/dashboard`로 이동한다.
- Given 없는 이메일 또는 틀린 비밀번호 / When 제출 / Then 어느 쪽인지 구분하지 않고 같은 오류를 표시한다 (계정 열거 방지).
- Given 연속 실패 / When 제한(이메일당 10회/시간, IP당 30회/시간) 초과 / Then 잠시 후 다시 시도하라고 안내한다.
- Given 익명 상태에서 로그인 / When 성공 / Then 익명으로 입력한 데이터는 이어지지 않는다. 로그인 화면에서 미리 고지한다.

### 2.2 온보딩 (ONBD)

**US-O1. 단계별 자동 저장과 재개**
> 사용자로서, 온보딩을 중단해도 입력한 내용이 남아 이어서 진행하고 싶다.

- Given 단계 입력 중 / When 필드 값 변경 후 2초 경과 또는 단계 이동 / Then 서버에 자동 저장되고 `자동 저장됨` 상태가 표시된다. 단, 원자 단위 저장이 필요한 입력(소득: 금액+유효일, 스킬: 스킬+기간+사용일)은 필수 조합이 완비된 시점에 저장하고, 그 전에는 화면 상태로만 유지한다.
- Given 온보딩 중단 후 재로그인 / When 진입 / Then 마지막 미완료 단계에서 기존 입력이 채워진 상태로 재개된다.
- Given 저장 API 실패 / When 재시도에도 실패 / Then 입력값을 화면에 보존하고 오류 배너를 표시한다. 입력을 초기화하지 않는다.

**US-O2. 프로필 입력 (S-05)**

- Given 프로필 단계 / When 주 직무, 총 경력, 희망 지역, 고용 형태 입력 / Then 다음 단계로 진행할 수 있다. 회사 규모는 건너뛸 수 있다.
- Given 필수값 누락 / When 다음 시도 / Then 누락 필드에 인라인 오류를 표시하고 이동을 막는다.

**US-O3. 소득 입력 (S-06)**

- Given 소득 단계 / When 세전 연봉과 유효 시작일이 모두 완비 / Then `POST /income`으로 이력 1건이 생성된다. 이후 같은 항목의 수정은 `PUT /income/{id}`를 사용한다 (반복 POST 금지 — 유효일 유니크 충돌). 월 실수령액은 선택 입력이다.
- Given 실수령액 미입력 / When 저장 / Then `구매력 계산은 세전소득 기반 추정으로 표시됩니다` 안내를 노출한다.
- Given 과거 연봉 이력 추가 / When 같은 유효 시작일 중복 / Then 저장을 거부하고 기존 항목 수정을 안내한다.

**US-O4. 소비 입력 (S-07)**

- Given 소비 단계 / When 6개 카테고리 중 일부만 금액 입력 / Then 저장은 허용하고, 미입력 카테고리는 카테고리 단위 `통계청 평균 기준`(`DEFAULT_CPI`)으로 보완하며 해당 월 요약 상태는 `일부 추정 포함`(`PARTIALLY_ESTIMATED`)으로 안내한다.
- Given 금액 입력 / When 합계가 실수령액(입력된 경우) 초과 / Then 경고를 표시하되 저장은 허용한다.

**US-O5. 스킬 입력 (S-08)**

- Given 스킬 단계 / When 검색어 입력 / Then 표준 스킬 사전에서 별칭 포함 자동완성 결과를 보여준다.
- Given 사전에 없는 스킬 / When 직접 추가 / Then 사용자 정의 스킬로 저장하고 `시장 수요 통계가 제공되지 않을 수 있습니다`를 안내한다.
- Given 스킬 선택 / When 실무 사용 개월 수와 마지막 사용일 입력 / Then 항목이 추가된다. 동일 정규화 스킬 중복 추가는 거부한다.
- Given 스킬 0개 / When 다음 시도 / Then 최소 1개 입력을 요구한다.

**US-O6. 검토와 완료 (S-09)**

- Given 검토 단계 / When 진입 / Then 입력 요약, 기본값으로 대체된 항목 목록, 계산 제한 사항(추정 라벨 예정 항목)을 표시한다.
- Given 검토 화면 / When 항목별 `수정` 선택 / Then 해당 단계로 이동하고 완료 후 검토로 복귀한다.
- Given 검토 확인 / When 완료 제출 / Then 온보딩 완료 상태가 저장되고 첫 지수 계산이 요청되며 `/dashboard`로 이동한다.

### 2.3 대시보드 (DASH)

**US-D1. 3대 지표 확인 (S-10)**

- Given 계산 가능한 데이터 / When 대시보드 진입 / Then 구매력 지수, 시장가치 지수, 결정 신호를 이전 스냅샷 대비 변화와 함께 표시한다.
- Given 각 지표 카드 / When 근거 펼치기 / Then 적용된 규칙, 사용 데이터 기준일, 규칙 버전, 제외된 데이터와 이유를 표시한다.
- Given 소비 가중치 상태 / When 지수 표시 / Then `내 지출 기준`, `일부 추정 포함`, `이전 지출 기준`, `통계청 평균 기준` 중 해당 뱃지를 함께 표시한다 (enum 4종: `USER_DEFINED`/`PARTIALLY_ESTIMATED`/`PROPAGATED`/`DEFAULT_CPI`).

**US-D2. 데이터 상태 구분**

- Given 동료집단 완화 적용 / When 시장가치 표시 / Then 실제 적용된 비교 조건(예: `서울 전체 / 경력 4~7년(MID) / 회사규모 무관`)을 저장 브래킷 단위로 명시한다.
- Given 표본 수 미달(N < 10) / When 지수 요청 / Then 수치 대신 `표본 부족` 상태와 현재 표본 수를 표시한다. 임의 수치를 만들지 않는다.
- Given 외부 데이터 수집 실패 / When 대시보드 조회 / Then 마지막 성공 데이터 기준으로 표시하고 `업데이트 지연`과 기준일을 노출한다.

**US-D3. 차트 (S-14)**

- Given 12개월 이상 데이터 / When 소득 vs 물가 탭 / Then 소득 지수선(`incomeIndex`)과 개인물가 지수선(`personalPriceIndex`)을 기준월 100 지수 2계열로 표시하고, 소득선이 물가선 아래인 구간에 구매력 손실 음영을 칠한다. 원화 금액은 툴팁 보조 정보로만 노출한다 (원화·지수 축 혼용 금지 — UI §4.1과 동일).
- Given 공개연봉 표본 존재 / When 연봉 분포 탭 / Then 판정 기준선은 공식 임금통계 중앙값이며, 공고 공개연봉 분포(최소·25%·중앙값·75%·최대)는 참고로 병기하고 사용자 위치 핀, 표본 수, 결측률을 함께 표시한다.

**US-D4. 스냅샷 이력 (S-11)**

- Given 2개월 이상 스냅샷 / When 이력 화면 진입 / Then 월별 두 지수와 결정 신호 변화를 시간순으로 표시한다.
- Given 특정 월 선택 / When 상세 보기 / Then 해당 월의 근거, 데이터·규칙 버전을 표시한다.

### 2.4 12개월 시나리오 (SCEN)

**US-S1. 잔류 vs 이직 비교 (S-15)**

- Given 시뮬레이터 화면 (S-15) / When 예상 인상률, 이직 목표 연봉, 이직 일회성 비용, 예상 공백 기간, 실업급여 수급 요건 충족 여부(`isEligibleForUnemploymentBenefit`) 입력 / Then 잔류 보상, 이직 보상(요건 충족 시 실업급여 반영, 미충족 시 급여 0), 차이를 계산해 표시한다.
- Given 계산 결과 / When 표시 / Then 차이를 `추정 추가보상` 또는 `추정 기회비용`으로 라벨링하고, 세금·성과급·주식보상·퇴직금이 미반영임을 문구로 명시한다.
- Given 입력값 변경 / When 재계산 / Then 이전 결과를 덮어쓰기 전 로딩 상태를 표시하고 완료 후 갱신한다.
- Given 시나리오 저장 / When 계산 완료 / Then 입력 가정과 결과를 `CareerScenario`로 보존해 재방문 시 마지막 시나리오를 복원한다.

### 2.5 이력 관리 (REC)

**US-R1. 소득·소비·스킬 이력 CRUD (S-12)**

- Given 이력 화면 / When 연봉 이력 추가·수정 / Then 유효 시작일 기준으로 반영되고 지수 재계산이 요청된다.
- Given 소비 기록 / When 특정 기준월 수정 / Then 해당 월 이후의 가중치 전파(`PROPAGATED`)가 재계산된다.
- Given 스킬 삭제 / When 확인 / Then 시장가치 지수에서 제외되고 다음 계산부터 반영된다.
- Given 미래 날짜 입력 / When 저장 시도 / Then 거부하고 오류를 표시한다.

### 2.6 사용자 설정 (USER)

**US-C1. 세션 관리 (S-13)**

- Given 로그인 상태 / When 모든 기기에서 로그아웃 선택 / Then 전체 세션이 폐기되고 로그인 화면으로 이동한다.

**US-C2. 사용자 및 개인 데이터 삭제**

- Given 설정 화면 / When 삭제 요청 / Then 삭제 범위(프로필, 입력 이력, 스냅샷, 시나리오, 세션, 사용자 행)를 고지하고 확인받는다. 등록 사용자는 이메일 재입력, 익명 사용자는 이메일이 없으므로 확인 문구 입력으로 대신한다.
- Given 삭제 확인 / When 실행 / Then 개인 데이터를 삭제하고 완료 화면을 표시한다. 공용 시장 집계 데이터는 영향받지 않는다.

## 4. 계산 경계 규칙

[도메인 정의서](domain-logic.md)의 계산 공식이 다루지 않는
경계·예외 조건을 정의한다.

### 4.1 스킬 수요 지수

```text
스킬 수요 지수 = 최근 3개월 수요율 ÷ 그 이전 12개월(4~15개월 전, 비중첩) 수요율 × 100
```

- **분모 0 (이전 12개월 창(4~15개월 전) 관측 없음):** 지수를 계산하지 않고 `신규 관측` 상태로 표시한다. 시장가치 지수 가중합에서 제외하고 별도 목록에 노출한다.
- **분자 0 (최근 3개월 관측 없음):** 지수 0이 아닌 `최근 수요 없음` 상태로 표시하고 가중합에는 0으로 반영한다.
- **이상치 클램프:** 지수를 [25, 400] 범위로 제한한다. 클램프 적용 시 근거에 `이상치 보정 적용`을 표기한다. (후보값, 데이터 검증 후 확정)

### 4.2 시장가치 지수(MVI)

- 가중치 계산 가능한 스킬이 0개면 MVI를 표시하지 않고 `표본 부족`을 반환한다.
- 사용자 정의 스킬은 시장 집계 매칭이 없으므로 가중합에서 제외하고 `통계 미제공` 상태로 표시한다.
- 제외 스킬의 가중치는 나머지 스킬에 재정규화한다 (총합 1 유지).

### 4.3 구매력 지수(PPI)

- **기준월:** 소득 이력과 소비 가중치(직접 입력 또는 기본값)가 모두 존재하는 첫 번째 월. 기준월 산정에 사용된 데이터 출처를 스냅샷에 기록한다.
- **CPI 최신월 결측:** 해당 월 지수를 생성하지 않고 마지막 계산월과 `업데이트 지연`을 표시한다. 보간하지 않는다.
- **소득 이력 1건뿐:** 지수는 100 단일점으로 표시하고 `비교 기간 부족` 안내를 노출한다.

### 4.4 스냅샷 멱등성과 재계산 범위

- 스냅샷 키는 `(user_id, base_year_month, 데이터 버전, 규칙 버전)`. 동일 키 재실행은 기존 행을 대체하며 중복 행을 만들지 않는다.
- 사용자 입력 변경 시 새 데이터 버전을 발급하고, 변경의 가장 이른 유효월부터 현재까지의 스냅샷을 새 버전으로 재계산해 저장한다. 과거 소비 수정에 따른 가중치 전파(US-R1) 재계산도 이 규칙을 따른다.
- 조회는 월별 최신 `(데이터 버전, 규칙 버전)` 스냅샷을 사용하고, 이전 버전 행은 근거 추적용으로 보존한다.
- 상세 DDL과 대체 의미론은 [상세 기술 명세 §1.3](technical-specification.md)을 따른다.

## 5. 화면별 상태 명세

모든 화면은 공통으로 로딩 / 정상 / 오류 상태를 구현한다 (전 화면 공통 규칙이므로
화면별로 반복 명세하지 않는다). 아래 표는 공통 규칙 외에 별도 설계가 필요한
비어있음·열화(degraded) 상태만 정의한다.

| 화면 | 비어있음 | 열화 상태 | 오류 |
| --- | --- | --- | --- |
| S-10 대시보드 | 첫 계산 전: `첫 지수를 계산하고 있습니다` + 예상 소요 안내 | `표본 부족`, `업데이트 지연`, `추정` 뱃지 카드별 표시 | 재시도 버튼 + 마지막 성공 데이터 유지 |
| S-11 이력 | 스냅샷 1개 이하: `다음 달부터 변화를 볼 수 있습니다` | 일부 월 누락 시 갭 표시 (선 연결 금지) | 재시도 |
| S-12 이력 관리 | 항목 없음: 추가 유도 | — | 저장 실패 시 입력 보존 |
| S-14 추이분석 | 12개월 미만 데이터: 차트 대신 안내 문구 | `표본 부족`(N<10), 업데이트 지연 시 마지막 성공 데이터 + 지연 배지 (US-D2 기준 동일 적용) | 재시도 버튼 + 마지막 성공 데이터 유지 |
| S-15 시뮬레이터 | 미입력: 기본값 채움 없이 입력 유도 | 실업급여 조건 미충족 가정 시 안내 | 계산 실패 시 이전 결과 유지 + 오류 표시 |

공통 원칙:

- 열화 상태에서도 화면을 비우지 않고 마지막 성공 데이터 + 상태 라벨을 보여준다.
- 오류 메시지에 내부 코드·스택을 노출하지 않는다.
- 모든 추정·대체 값은 시각적으로 실측값과 구분한다 (뱃지 또는 점선).

## 6. 설계 기준과 미결 항목

### 6.1 설계 계보

제품 기능은 MVP 설계 라인(온보딩 5단계, 이력 관리, 계정 삭제)을, 데이터 아키텍처는
파이프라인 재설계(원천 4개, 임금통계 기준선, RawIngest·dedup, 원천별 집계 후 표본수
가중 결합)를 따른다.

**인증만 재설계 쪽으로 돌아왔다.** 초대 베타·매직링크 전제를 걷고 익명 세션 우선 +
선택적 비밀번호 계정으로 바꿨다. 사용자 실체가 본인과 방문자뿐이라 초대 게이트가
지킬 대상이 없었고, 이메일 발송 경로가 평가자의 진입을 오히려 막았기 때문이다.

**계보가 갈린 배경:** 파이프라인 재설계가 MVP 설계 전체 대체를
선언했으나, 이후 상세 문서군(API·DB·UI·워크플로우)이 구 MVP 라인을 그대로
따르며 계보가 두 갈래로 분기했다. 재설계는 제품을 포트폴리오·학습용으로 축소(본인+
데모 계정, 매직링크 제거)하고 지수를 개명했으나, 상세 문서군 작업 전부가 초대 베타
제품 라인 기준이었다. 인증에 한해서는 재설계의 판단이 옳았던 것으로 확인돼 그쪽을
채택했다.

**검토한 대안:**

- **A. MVP 설계 라인 전면 유지, 재설계 폐기** — 데이터 리스크(고용24 커버리지, 공개연봉
  결측) 미해결.
- **B. 파이프라인 재설계 전면 채택** — 인증·온보딩·삭제 등 상세 문서군 산출물 대규모 재작업.

둘 다 접고 하이브리드로 정리했다 — 제품은 이미 완성도 높은 MVP 설계 라인을 유지하고,
데이터는 실측으로 드러난 리스크를 해결한 파이프라인 재설계를 채택한다.

문서 간 충돌 시 이 §6.1을 따르고, 그래도 어긋나면 최신 커밋을 우선한다. 리뷰
라운드별 세부 수정 이력은 git 커밋 히스토리를 참조한다.
