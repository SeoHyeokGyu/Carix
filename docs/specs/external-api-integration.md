# Carix 외부 원천 API 연동 명세 (External Source API Integration)

| 항목 | 내용 |
| --- | --- |
| 대상 독자 | 수집기(collector) 어댑터 구현자 |
| 상위 문서 | [데이터 아키텍처](data-architecture.md), [도메인 정의서](domain-logic.md) |

## 목적과 범위

수집기(collector)의 **원천 어댑터 경계**만 정의한다. 호출 방법, 파라미터, 응답 필드, 실측
가용 범위, 오류 코드가 대상이다.

- 내부 REST 계약은 [API 규격](api-specification.md)을 따른다. 여기서 반복하지 않는다.
- 계산 공식은 [도메인 정의서](domain-logic.md)를 따른다. 여기서 반복하지 않는다.
- 카테고리 매핑·기본 가중치 값은 `config/cpi-category-map.yml`,
  `config/default-expense-weights.yml`이 정본이다.

이 문서는 [기능 분해 명세 §6.2](functional-specification.md) 미결 항목 중
`KOSIS 이용 조건`과 `기본 소비 가중치 6개 값`을 해소한다. 해당 표는 이 문서와
별도로 관리되므로 갱신 시 함께 확인한다.

## 2. KOSIS (검증 완료)

### 2.1 공통

| 항목 | 값 |
| --- | --- |
| 인증 | 쿼리 파라미터 `apiKey` |
| 키 보관 | `.env`의 `KOSIS_API_KEY` (저장소 커밋 금지) |
| 프로토콜 | HTTPS. `http://`는 302 리다이렉트 |
| 응답 포맷 | `format=json&jsonVD=Y` |
| 심의 | 자동승인 |

**서비스별 엔드포인트가 다르다.**

| 용도 | 엔드포인트 |
| --- | --- |
| 통계표 검색 | `https://kosis.kr/openapi/statisticsSearch.do?method=getList` |
| 통계목록 | `https://kosis.kr/openapi/statisticsList.do?method=getList` |
| **메타데이터** | `https://kosis.kr/openapi/statisticsData.do?method=getMeta` |
| **통계자료** | `https://kosis.kr/openapi/Param/statisticsParameterData.do?method=getList` |

메타와 자료의 호스트 경로가 다르다. 자료 조회에 `statisticsData.do`를 쓰면 실패한다.

`getMeta`의 `type`은 `ITM`을 사용한다. `type=CL`은 이 통계표들에서 `err 30`을
반환한다 — 데이터 없음이지 잘못된 호출이 아니므로 재시도 대상이 아니다.

### 2.2 오류 코드 (실측)

| err | errMsg | 실제 의미 | 어댑터 처리 |
| --- | --- | --- | --- |
| `11` | 유효하지않은 인증KEY입니다 | 키 무효·미활성 **또는 키 문자열 손상** | 재시도 금지. 운영자 알림 |
| `20` | 필수요청변수값이 누락되었습니다 | 필수 파라미터 누락. 괄호로 누락 축 표기 (예: `(objL)`) | 재시도 금지. 버그 |
| `21` | 잘못된 요청 변수를 호출 하였습니다 | 파라미터 값·축 순서 오류 | 재시도 금지. 버그 |
| `30` | 데이터가 존재하지 않습니다 | 해당 조건 데이터 없음 | 정상 응답으로 처리. 결측 기록 |

오류는 HTTP 200 + JSON 객체로 온다. 정상 응답은 JSON **배열**이다.
`isinstance(response, list)` 여부로 성공을 판정한다. HTTP 상태 코드로 판정하면
전부 성공으로 오인한다.

> **함정 — 인증키 끝 `=`**
> KOSIS 키는 base64 문자열이며 패딩 `=`로 끝난다. 44자 중 마지막 `=`가 빠진
> 43자 키는 `err 11`을 반환하며, 이는 **미승인 키와 응답이 구분되지 않는다.**
> `err 11` 발생 시 승인 상태를 의심하기 전에 키 길이(44자)부터 확인한다.
> URL 인코딩(`%3D`) 여부는 무관하다 — 양쪽 다 동작한다.

### 2.3 축 순서 (핵심 함정)

통계표마다 분류 축의 순서가 다르며, `getMeta&type=ITM` 응답의 **`OBJ_ID_SN`**이
축 번호다. `OBJ_ID_SN=1` → `objL1`, `=2` → `objL2`.

`DT_1J22001` 실측:

| OBJ_ID | OBJ_NM | OBJ_ID_SN | 파라미터 |
| --- | --- | --- | --- |
| `C` | 시도별 | 1 | `objL1` |
| `I` | 지출목적별 | 2 | `objL2` |

축을 바꿔 넣으면 **빈 배열이 아니라 `err 21`**이 온다. 조용한 실패가 아니므로
어댑터에서 즉시 드러난다. 새 통계표 추가 시 `OBJ_ID_SN`을 반드시 먼저 조회한다.

### 2.4 CPI — `DT_1J22001`

지출목적별 소비자물가지수(품목포함, 2020=100). 구매력 지수의 원천.

| 항목 | 값 |
| --- | --- |
| `orgId` | `101` |
| `tblId` | `DT_1J22001` |
| `itmId` | `T` (소비자물가지수) |
| `objL1` | `T10` (전국) |
| `objL2` | 지출목적 코드. 12대 분류 `A`~`L`, 총지수 `0` |
| `prdSe` | `M` (월) |
| 기간 지정 | `startPrdDe`/`endPrdDe` (`YYYYMM`) 또는 `newEstPrdCnt=N` (최근 N개) |

**실측 가용 범위: 1985-01 ~ 2026-06 (498개월).**
최신 공표월은 2026-06 → **공표 지연 약 1개월**. 관리자의 월 1회 직접 구동 또는 Spring Scheduler 월 1회 등록으로 충분.

수집기는 총지수 `0` 과 `A`~`L` 을 한 호출로 받아 `core.cpi_observation.category` 에 코드 원값(`0`, `A`~`L`)으로 저장한다. 총지수는 카테고리 합성에 섞이지 않고 전체 CPI 전년동월비(개인물가 비교 기준)로만 읽힌다.

과거 전체 시계열을 한 번에 받을 수 있다 → **구매력 지수는 백필 가능**.
(채용공고 원천과 대비된다. §3.1 참조)

호출 예:

```
https://kosis.kr/openapi/Param/statisticsParameterData.do
  ?method=getList&apiKey=${KOSIS_API_KEY}
  &orgId=101&tblId=DT_1J22001
  &itmId=T&objL1=T10&objL2=0+A+B+C+D+E+F+G+H+I+J+K+L
  &prdSe=M&startPrdDe=198501&endPrdDe=202606
  &format=json&jsonVD=Y
```

응답 행의 주요 필드:

| 필드 | 의미 |
| --- | --- |
| `PRD_DE` | 기준 시점 (`YYYYMM`) |
| `DT` | 지수값 (문자열) |
| `C1` / `C1_NM` | objL1 코드·명 (시도) |
| `C2` / `C2_NM` | objL2 코드·명 (지출목적) |
| `UNIT_NM` | `2020＝100` (전각 등호 주의) |
| `TBL_ID`, `ORG_ID` | 원천 식별자 — RawIngest에 보존 |

### 2.5 가계동향조사 — `DT_1L9U101`

가구당 월평균 가계수지 (전국, 1인이상). 기본 소비 가중치(`DEFAULT_CPI`)의 원천.

| 항목 | 값 |
| --- | --- |
| `orgId` | `101` |
| `tblId` | `DT_1L9U101` |
| `itmId` | `T110` (전체가구) |
| `objL1` | 가계수지항목 코드. 소비지출 합계 `F`, 12대 비목 `H`,`J`,`K`,`L`,`M`,`N`,`O`,`P`,`Q`,`S`,`T`,`U` |
| `prdSe` | `Y` (연) |

**실측 최신: 2025년.** 소비지출 월평균 2,939,091원.

> **폐기 주의:** 문서 초기 서술이 지목한 `DT_1L9E102`는 **2016년에서 시계열이
> 끊긴다** (가계동향조사 개편). 현행 시리즈는 `DT_1L9U101`이다.

연 1회 공표이므로 배치 대상이 아니다. 값이 갱신되면
`config/default-expense-weights.yml`의 `version`을 올린다. 재적재 방식은 구현 시 정한다 —
core-api 는 Flyway 를 쓰지 않는다 — `core` 스키마는 DDL 을 직접 적용한다.

### 2.6 코드 충돌 — 어댑터 최대 위험

CPI와 가계동향은 **같은 12대 분류를 쓰지만 코드 문자가 다르다.**

| 분류 | CPI (`DT_1J22001`) | 가계동향 (`DT_1L9U101`) |
| --- | --- | --- |
| 01 식료품·비주류음료 | `A` | `H` |
| 04 주거·수도·광열 | `D` | `L` |
| 06 보건 | `F` | `N` |
| 08 통신 / 정보통신 | `H` | `P` |
| 11 음식·숙박 | `K` | `T` |
| 12 기타 | `L` | `U` |

`A`·`F`·`H`·`K`·`L`은 **양쪽 코드계에 모두 존재하며 의미가 다르다.** 두 코드를
하나의 조회 테이블로 합치면 예외 없이 조용히 잘못된 값이 나온다.

- 코드계를 필드명으로 구분한다: `cpi` / `hhCode`
  (`config/default-expense-weights.yml` 스키마와 동일)
- 어댑터는 자기 원천의 코드계만 다루고, 상호 변환은 config 파일을 통해서만 한다.

### 2.7 카테고리 CPI 합성 규약

Carix 6 카테고리는 CPI 12대 분류의 N:1 합성이다. 합성은 **변화율에만** 적용한다.

```text
올바름: categoryRate(t) = Σ( subWeight_i × ( CPI_i(t) / CPI_i(t-1) - 1 ) )
틀림  : categoryIndex(t) = Σ( subWeight_i × CPI_i(t) )
```

지수 레벨을 가중평균하면 기준시점이 재설정되어 실제 카테고리 계열과 어긋난다.
값이 그럴듯하게 나오므로 단위 테스트 없이는 드러나지 않는다.

`subWeight`는 `config/default-expense-weights.yml`을 사용한다.

## 3. KOSIS 외 원천 (결론 3)

§2 처럼 실측된 호출 명세가 아니라 **원천 채택 여부의 결론**이다. 고용24·사람인·임금통계
3건 전부 결론이 났다 — 앞의 둘은 경로가 막히거나 폐기됐고, 임금통계는 채택된 뒤
호출 규격이 §2.4·§2.5 와 같은 KOSIS 공통 경로를 그대로 쓴다.

### 3.1 고용24 채용공고 — **경로 차단됨**

> **결론: work24.go.kr 직접 연동은 개인 계정으로 불가능하다.**
> 대체 경로는 공공데이터포털(data.go.kr)이며, 별도 활용신청이 필요하다.

실측 내용:

| 확인 | 결과 |
| --- | --- |
| 인증키 발급 | 채용정보 / 공통코드 / 훈련과정 3건 승인 |
| 채용정보 목록 `wk/callOpenApiSvcInfo210L01.do` | `개인회원은 사용할 수 없는 OPEN-API입니다` |
| 채용정보 상세 `wk/callOpenApiSvcInfo210D01.do` | 동일 오류 |
| 훈련과정 `hr/callOpenApiSvcInfo310L01.do` | **정상 동작** (689,382건 조회) |
| 구 워크넷 `openapi.work.go.kr/opi/opi/opia/wantedApi.do` | `유효하지 않은 인증키` — 별도 키 체계 |

고용24 공식 안내는 `OPEN-API는 고용24 기업회원 전용 서비스`로 명시한다. 키는
발급되지만 호출 단계에서 계정 유형으로 차단된다. **파라미터 문제가 아니므로
재시도·파라미터 조정으로 해결되지 않는다.** 등록일 범위 파라미터를 붙여도 같은
오류가 반환된다.

훈련과정 API가 같은 계정에서 동작하므로 계정·키 자체는 유효하다. 차단은
채용정보 계열 서비스에 한정된다.

#### 공공데이터포털은 대체 경로가 아니다

`한국고용정보원_워크넷 채용정보 채용목록 및 상세정보`
(`data.go.kr/data/3038225/openapi.do`)는 **API 유형이 LINK**다. data.go.kr에서
인증키를 발급하지 않고 `바로가기`로 work24 신청 페이지로 이동시킨다. 따라서
기업회원 제약을 그대로 상속하며 우회 경로가 되지 못한다.

명세상 요청 파라미터에 `등록일`·`구인시작일`·`구인종료일`이, 응답에
`최소임금액`·`최대임금액`이 있으나 **호출 자격이 없으므로 의미가 없다.**
계정 유형이 기업회원으로 바뀌면 그때 재검토한다.

#### 결론: 고용24 어댑터는 구현하지 않는다

개인 계정으로 접근 가능한 채용 관련 API는 채용행사·공채속보·공채기업정보뿐이며,
셋 다 스킬 수요율 산출에 쓸 수 없다.

[데이터 아키텍처 §1.2](data-architecture.md)의 `검증 결과가 나쁜 원천은 어댑터만
비활성화한다` 규칙을 적용한다. 파이프라인 구조는 그대로 두고 `Work24Adapter`를
구현하지 않는다. 채용공고 원천 구성은 [데이터 아키텍처 §1.1](data-architecture.md)이
소관이며 Work24 는 포함하지 않는다.

#### 참고: 훈련과정 API

`hr/callOpenApiSvcInfo310L01.do`는 동작하나 MVP 범위 밖이다. 스킬 보강 신호의
후속 확장 후보로만 기록한다. 지금 연동하지 않는다.

### 3.2 사람인 — **공식 API 경로 폐기**

> **결론: 사람인 채용정보 공식 API 는 쓰지 않는다.**
> 채용공고는 스크래핑으로 수집한다.

문서 규격만 검토했고 키 미발급으로 호출 실측은 하지 않았다. API 의 `keyword`
응답 필드에 기대던 스킬 추출 설계도 함께 폐기됐다 — 본문 텍스트에서
[도메인 정의서 §7.2](domain-logic.md)의 토큰 경계 매칭으로 스킬을
뽑는다.

#### 결론: 사람인 어댑터는 API 로 구현하지 않는다

`SaraminAdapter`·`JobKoreaAdapter`는 스크래핑으로 구현한다. 채용공고 원천 구성과 파이프라인은
[데이터 아키텍처 §1](data-architecture.md)을 따른다. 스크래핑 대상 사이트의
이용약관은 검토하지 않기로 했고, 그 전제와 재검토 시점은 [데이터 아키텍처 §3](data-architecture.md)이 갖는다.

#### 상세페이지 급여 표기

공고 연봉은 상세페이지의 두 자리에서 읽으며 의미가 다르다. 판정 규칙은
[데이터 아키텍처 §1.3](data-architecture.md)이 소관이다.

- **`<meta name="description">` 의 「급여」 문구(잡코리아·사람인).** 공고 본문에 적힌 그대로다 —
  「연봉 4,610만원 이상」, 「월급 500~600만원(면접 후 결정)」처럼 금액이 보이면 공개 연봉이고,
  「회사내규에 따름」·「면접 후 결정」·「협의」만 있으면 공개된 금액이 없다. 띄어쓰기 변형(「회사내규」·「회사 내규」)이 있다.
- **잡코리아 `pay` 블록.** 상세페이지 JSON-LD 에도 `baseSalary` 가 실리는 것이 관측되지만 수집기는 읽지 않고 RSC `pay` 블록만 읽는다. 본문이 회사내규여도 회사가 검색 필터용으로 넣은 구간이 실리며
  (`2590~10001` 등, 상한은 미포함 경계) 공개 연봉이 아니다. 비공개 검색 구간으로만 보관한다.

### 3.3 임금통계 — **KOSIS 24계층 보간 채택**

> **결론: KOSIS 근로실태조사(`DT_118N_PAYM39`)의 임금계층 24구간에 누적분포 보간을
> 적용해 `core.wage_stat_observation` 기준선으로 쓴다.**
> 후보 B(한국고용정보원 직업별 임금정보)는 개발자 직군이 데이터에 없어 탈락했다.
> 아래 A안 실측은 **탈락 근거가 아니라 채택한 원천의 한계 목록**이다 — 보간이 메운
> 것은 중앙값 축뿐이고 직종·경력·지역 세 축은 그대로 남았다.

임금직무정보시스템(`wage.go.kr`) OpenAPI는 공공데이터포털에 등록돼 있지 않다.
채택한 KOSIS 고용형태별근로실태조사 계열은 [데이터 아키텍처 §2.2](data-architecture.md)가
요구하는 **직무 × 경력 × 지역 중앙값** 네 축 중 중앙값만 충족한다.

#### 실측 결과 A안 — 채택 (KOSIS 고용형태별근로실태조사, `orgId=118`, 최신 2025년)

| 요구 차원 | 실측 |
| --- | --- |
| 중앙값 | **도출 가능** — `DT_118N_PAYM39`가 임금계층 24구간 근로자수 분포 제공. 누적분포 보간으로 중위 산출 |
| 직종 | **대분류 10개뿐** (`2018_KECO`). 개발·데이터·AI가 `전문가 및 관련종사자(2)`에 묻힌다 |
| 경력 | **없음.** 연령 11구간이 유일한 프록시. `평균근속년수`는 차원이 아니라 항목값 |
| 지역 | **없음.** 시도별 임금 통계(`DT_118N_MON060` 등)는 산업·규모 차원이며 직종이 없다 |

관련 통계표:

| 통계표 | 제공 | 한계 |
| --- | --- | --- |
| `DT_118N_PAYM39` | 직종 × 성별 × **임금계층 24구간** × 연령, 근로자수 | 중앙값 보간용. 직종 대분류 |
| `DT_118N_PAYM42` | 직종 × 학력 × 성별 × 연령, 월임금총액 | **평균만** |

검증 호출 예 (실제 동작 확인):

```

누적분포 보간 결과 중앙값 구간 = 월 350~400만원
```

축 코드 주의: `PAYM39`는 `...205073...`, `PAYM42`는 `...205070...` 접두를 쓴다.
통계표마다 다르므로 §2.3 절차대로 `getMeta&type=ITM`으로 매번 확인한다.

`전문가 및 관련종사자` 대분류는 개발자·간호사·교사·회계사를 한 묶음으로 다룬다.
**이 해상도 한계는 채택 후에도 남아 있다** — 연봉 격차와 결정 신호
([기능 명세 §12.4](functional-specification.md))는 직무 대분류 기준선 위에서 판정된다.
경력 축은 연령대(`AGEGRADE` 20~24세 신입 … 40~44세 리드)를 프록시(`AGE_BAND_PROXY`)로
매핑해 사용하며, 화면과 API(`b12`)에서 `basis: "AGE_BAND_PROXY"`로 그 성격을 투명하게 밝힌다.

    2. **3중 안전장치 정식 규범화:** 프록시 기준선(`AGE_BAND_PROXY`)의 한계가 사용자 판단을 왜곡하지 않도록 다음 규범을 시스템 불변식으로 확정한다:
       - **기준선 성격 투명 고지 (`b12`):** 대시보드 메인(`S-10`), 연봉 분포·경력 사다리(`S-14`), 관리자 데이터 탐색(`S-20`)에서 `basis: "AGE_BAND_PROXY"`(연령대 기반 추정치, 전 직무 공통)와 연령대-경력 매핑 근거(신입 20~24세 … 리드 40~44세)를 상시 노출한다.
       - **결정 신호 교차 판정 및 부분 판정 격리 (`c23`):** 결정 신호(Rule Matrix)는 `SalaryGapRatio` 단독으로 결정되지 않고 시장가치 지수(`MVI`) 및 구매력 지수(`PPI`)와 결합 평가된다. MVI가 없는 부분 판정(규칙 1.1.0)에서는 연봉 격차가 크더라도 공격적인 `이직 탐색`(`SEEK_JOB`)을 차단하고 `협상 검토`로 낮춘다.
       - **실측 채용공고 연봉 분포 병행 노출 (`b10`, `c27`, `c28`):** 공식 기준선 옆에 동료집단 공개 연봉 10건 이상 실측 표본 분포(`peerSalaryDistribution`)를 함께 제시하여, 국가 통계 프록시 기준선과 실제 노동 시장의 채용 제시 연봉을 사용자가 교차 확인할 수 있게 한다.

### 3.4 점핏 — **사람인 공고 보강 원천**

점핏은 사람인 계열 개발자 전용 채용 서비스다. 점핏 공고 번호는 사람인 공고 번호(`rec_idx`)와 같아 공고 행은 사람인(`SARAMIN`)으로 저장하고, 수집 이력(`raw_ingest`)만 `JUMPIT` 로 남긴다. 보강·추가 규칙은 [데이터 아키텍처 §1.3](data-architecture.md)이 소관이다.

| 용도 | 호출 | 비고 |
| --- | --- | --- |
| 목록 | `GET https://jumpit-api.saramin.co.kr/api/positions?sort=reg_dt&highlight=false&page={N}` | 페이지당 16건. 마감 `closedAt`·직무 분류 `jobCategory`·기술 스택을 싣는다. 목록 한 페이지가 `raw_ingest` 한 건이다 |
| 상세 | `GET https://jumpit-api.saramin.co.kr/api/position/{id}` | 신규 공고의 게시일 `publishedAt` 에만 쓴다 |

- 요청 간격은 초당 1건이다. 404 는 로그 없이 건너뛰고, 그 밖의 200 아닌 응답은 경고 로그를 남긴다.
- 공고 한 건의 실패는 로그와 작업 요약 `errors` 로 세고 작업 전체를 멈추지 않는다. 공고 번호를 못 읽으면 저장하지 않고 `skipped` 로 센다.
- `jobCategory` 는 쉼표로 여러 분류가 붙는다. 우선순위 AI > DATA > DEVELOPER > OTHER 로 대표 직무군 하나를 고른다.

| 직무군 | 점핏 분류 |
| --- | --- |
| AI | 인공지능/머신러닝 |
| DATA | 빅데이터 엔지니어, DBA |
| DEVELOPER | SW/솔루션, HW/임베디드, 서버/백엔드 개발자, devops/시스템 엔지니어, 프론트엔드 개발자, 웹 풀스택 개발자, 정보보안 담당자, QA 엔지니어, 크로스플랫폼 앱개발자, 안드로이드 개발자, iOS 개발자, 게임 클라이언트 개발자, 게임 서버 개발자, VR/AR/3D, 웹퍼블리셔, 블록체인 |
| OTHER | 기술지원, 개발 PM (다른 개발 분류가 함께 있으면 그쪽이 이긴다) |

분류가 없는 공고는 잡코리아 직무군 판정기의 제목 규칙으로 판정하고, 못 가르면 `DEVELOPER`(개발자 전용 서비스)다.

### 3.5 원티드 — **개발 공고 원천(`WANTED`)**

공고 행과 수집 이력(`raw_ingest`) 모두 `WANTED` 다. 저장·집계 규칙은 [데이터 아키텍처 §1.3](data-architecture.md)이 소관이다.

| 용도 | 호출 | 비고 |
| --- | --- | --- |
| 목록 | `GET https://www.wanted.co.kr/api/v4/jobs?country=kr&tag_type_ids=518&job_sort=job.latest_order&years=-1&locations=all&limit=100&offset={N}` | 페이지당 100건, 개발 직군(518). 목록 한 페이지가 `raw_ingest` 한 건이다 |
| 공고 페이지 | `GET https://www.wanted.co.kr/wd/{id}` | `__NEXT_DATA__` 에 게시일 `confirm_time`·직군 태그·경력·지역·회사·고용형태·본문이 있다. 상위 태그가 518 이 아니거나 `__NEXT_DATA__` 가 없거나 페이지의 번호가 목록 번호와 다르면 건너뛴다 |
| 상세 API | `GET https://www.wanted.co.kr/api/v4/jobs/{id}` | 스킬 태그 `skill_tags` 만 쓴다. 페이지에 스킬 태그가 없어 새로 만들 공고(정기 수집·표본)만 연다 |

- 요청 간격은 초당 1건이다. 404 는 로그 없이 건너뛰고, 그 밖의 200 아닌 응답은 경고 로그를 남긴다.
- 경력 상한 `annual_to` 가 100 이면 상한 없음이라 비워 저장한다.
- 공개 연봉이 없어 급여는 `NONE` 이다. 직원 수를 얻지 못해 회사 규모는 `UNKNOWN` 이다.
- 직무군은 개발 하위 직군 태그에서 대표 하나를 고른다(AI > DATA > DEVELOPER > OTHER, AI 는 잡코리아 제목 규칙 포함).

| 직무군 | 원티드 개발 하위 직군 |
| --- | --- |
| DATA | 데이터 엔지니어 655, 데이터 사이언티스트 1024, 빅데이터 엔지니어 1025, BI 엔지니어 1022, DBA 10231 |
| AI | 머신러닝 엔지니어 1634 |
| OTHER | 프로덕트 매니저 876, 개발 매니저 877, 기술지원 1026, 하드웨어 엔지니어 672, 테크니컬 라이터 10536, CTO 795, CIO 793 |
| DEVELOPER | 위를 뺀 개발 하위 직군 전부 |

- 측정: 무작위 공고 번호의 약 80% 가 공고(나머지 404)이고 그중 개발 직군이 약 25%, 월 번호 폭이 약 6천이라 월 개발 공고가 약 1,200건이다. 월 표본 250건에 약 1,500 요청(페이지 약 1,250 + 상세 API 250)·약 25분이 든다. 30만 번대에도 게시일이 남아 있다.
- 원티드 `robots.txt` 는 브라우저가 아닌 요청에 403 을 줘 확인하지 못했다(공고 API·페이지는 200). 요청량을 수동 실행·초당 1건으로 묶는다.

### 3.6 프로그래머스 — **개발 공고 원천(`PROGRAMMERS`)**

공고 행과 수집 이력(`raw_ingest`) 모두 `PROGRAMMERS` 다. 저장·집계 규칙은 [데이터 아키텍처 §1.3](data-architecture.md)이 소관이다.

| 용도 | 호출 | 비고 |
| --- | --- | --- |
| 목록 | `GET https://career.programmers.co.kr/api/job_positions?page={N}&order=recent` | 페이지당 20건. 제목·회사·지역·경력·기술 태그(`position_tags`)·직무 분류(`job_categories`)·게시일·마감일을 싣는다. 목록 한 페이지가 `raw_ingest` 한 건이다 |
| 상세 | `GET https://career.programmers.co.kr/api/job_positions/{id}` | 단건 상세 조회용 |

- 요청 간격은 초당 1건이다. 404 는 로그 없이 건너뛰고, 그 밖의 200 아닌 응답은 경고 로그를 남긴다.
- 상시 채용 표시용 마감일(9000년 이상)은 비워(`null`) 저장한다. 공개 연봉이 없어 급여는 `NONE`, 회사 규모는 `UNKNOWN` 이다.
- 직무군은 직무 분류(`job_categories`)에서 우선순위 AI > DATA > DEVELOPER > OTHER 로 대표 하나를 고른다. 분류가 없으면 제목 규칙으로 판정하고 못 가르면 `DEVELOPER` 다.

| 직무군 | 프로그래머스 직무 분류 |
| --- | --- |
| AI | 인공지능, 머신러닝, 딥러닝, 인공지능/머신러닝, AI, ML |
| DATA | 데이터 엔지니어, 빅데이터 엔지니어, DBA, 데이터 분석가 |
| OTHER | 기술지원, 개발 PM, 기획, 디자인, QA |
| DEVELOPER | 위를 뺀 직무 분류 전부 |

## 4. 공통 어댑터 규약

원천별 세부와 무관하게 적용한다. 근거는 [데이터 아키텍처 §1.2](data-architecture.md).

- 어댑터는 도메인 지식 없이 원문을 표준 DTO로만 변환한다.
- 수집 이력은 `RawIngest`에 기록한다 (출처, 원문 ID, 수집 시각, 관측 월 — 원문 payload는 보관하지 않는다).
- 응답이 배열이 아니면 오류로 간주한다 (§2.2 — HTTP 상태로 판정 금지).
- 재시도는 네트워크 오류·5xx에만 적용한다. 파라미터 오류(`err 20`/`21`)는 버그이므로
  재시도하지 않는다.
- 원천 장애 시 마지막 성공 집계를 사용하고 `업데이트 지연`과 기준일을 노출한다.
- 검증 결과가 나쁜 원천은 어댑터만 비활성화한다. 파이프라인 구조는 바꾸지 않는다.
- API 키는 `.env`에서 주입한다. 값을 로그·예외 메시지·URL 기록에 남기지 않는다.
