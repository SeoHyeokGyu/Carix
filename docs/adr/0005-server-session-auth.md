# 0005. 서버 세션 단일 인증 (매직링크 + 쿠키)

- 상태: 채택
- 날짜: 2026-07-19

## 맥락

초기 API 규격이 인증 방식을 혼재 기술했다: HTTP-only 쿠키, bearer `Authorization`
헤더, 상태ful `session` 테이블을 동시에 언급하며 우선순위·포맷을 정하지 않았다.
클라이언트·서버 구현이 갈릴 수 있었다.

## 결정

**서버 세션 단일 방식**으로 통일한다.

- 인증은 초대 기반 이메일 매직링크로만 한다(비밀번호 없음). 링크는 15분 유효·1회 사용.
- 세션 토큰은 불투명(opaque) 값으로 HTTP-only + Secure 쿠키에 담고, 서버가 `session`
  테이블에서 검증한다. JWT·`Authorization` 헤더는 쓰지 않는다.
- 계정은 초대된 이메일이 매직링크를 처음 요청하는 시점에 생성하고, 토큰은 항상
  `account_id`에 바인딩한다(`magic_link_token.account_id NOT NULL`).
- 세션 기본 유효기간 30일, 개별·전체 기기 로그아웃 제공.

## 대안

- **JWT 무상태 세션** — 즉시 폐기(전체 로그아웃·강제 만료)가 어렵고, 민감데이터
  앱에서 토큰 유출 대응이 복잡하다.

## 결과

- 계정 열거 방지: 미초대 이메일에도 동일한 발송 안내 응답. 이메일당 5회/시간, IP당
  20회/시간 속도 제한.
- 매직링크 원본 토큰은 저장하지 않고 해시만 저장, `used_at`으로 재사용 차단.
- 상세는 [상세 기술 명세](../specs/2026-07-18-detailed-technical-specifications.md)와
  [보안 문서](../SECURITY.md)를 따른다.
