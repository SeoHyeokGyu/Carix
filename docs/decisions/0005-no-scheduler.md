# 0005. 정기 실행(`@Scheduled`)을 도입하지 않는다

| 상태 | 채택 |
| --- | --- |
| 소관 | Member B (collector), Member C (관리자 콘솔) |

## 맥락

CPI 수집(Job 1), 공고 수집(Job 2), 시장 집계(Job 3)는 주기 실행이 자연스러워 보인다 —
CPI 는 월 1회, 공고는 일·주 1회.

## 결정

정기 실행을 두지 않는다. 관리자 화면(`S-16`)과 내부 API(`/internal/pipeline/**`)로 **직접
구동**한다.

## 근거

정기 실행에는 수집 실패 재시도, 중복 실행 방지, 실패 관측 경로가 함께 따라온다. MVP 표본
규모(사용자 한 자릿수, 공고 4천여 건)에서 그만한 값을 하지 않는다.

## 검토한 대안

- **Spring Scheduler** — 위 셋을 다 지어야 한다
- **Spring Batch** — 재시도·청크·잡 이력을 주지만 실제로 필요해진 적이 없다. 미도입

## 영향

- 수집이 멈춰도 아무도 모른다. 관리자가 콘솔에서 돌려야 데이터가 는다
- 문서 여럿이 한때 "관리자 직접 구동 **또는** Spring Scheduler" 로 적고 있었다. 이 결정
  이후 남은 표현은 걷었다
- 필요해지면 다시 판단한다. 그때 재시도·중복 방지·관측을 같이 설계한다
