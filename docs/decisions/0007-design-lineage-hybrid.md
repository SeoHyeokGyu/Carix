# 0007. 설계 계보는 하이브리드

| 상태 | 채택 |
| --- | --- |
| 소관 | 전 레인. 문서 충돌 시 기준 |

## 맥락

설계 문서 계보가 두 갈래로 갈렸다.

- **파이프라인 재설계** — 데이터 리스크(고용24 커버리지, 공개연봉 결측)를 실측으로 드러내며
  원천 4개·임금통계 기준선·RawIngest·dedup 을 제시했다. MVP 설계 전체 대체를 선언했고,
  제품을 포트폴리오·학습용으로 축소(본인+데모 계정, 매직링크 제거)하고 지수를 개명했다
- **MVP 설계 라인** — 초대 베타 제품 라인. 온보딩 5단계, 이력 관리, 계정 삭제까지 상세
  문서군(API·DB·UI·워크플로)이 이 기준으로 작성돼 있었다

## 결정

**제품 기능은 MVP 설계 라인, 데이터 아키텍처는 파이프라인 재설계.** 인증만 재설계 쪽을
따른다.

## 근거

- 재설계가 지적한 **데이터 리스크는 실재**했다. 그쪽을 안 받으면 지표가 안 선다
- 그러나 재설계 이후 작업 **전부가 구 제품 라인 기준**이라 전면 채택은 재작업이 과대하다
- 인증은 재설계의 판단이 옳았다 — 초대 게이트가 지킬 대상이 없었다 ([ADR-0001](0001-server-session-auth.md))

## 검토한 대안

- **A. MVP 설계 라인 전면 유지, 재설계 폐기** — 데이터 리스크 미해결
- **B. 파이프라인 재설계 전면 채택** — 인증·온보딩·삭제 등 상세 문서군 대규모 재작업

## 영향

- 지수 개명(시장가치 지수 → 스킬 수요 지수)과 계정 축소는 **미채택**이다. 옛 문서에서 그
  표현을 보면 이 결정 기준으로 정리한다
- 문서 간 충돌 시 이 기준을 따르고, 그래도 어긋나면 최신 커밋을 우선한다
- 서술 정본은 [기능 명세 §6.1](../specs/functional-specification.md)
