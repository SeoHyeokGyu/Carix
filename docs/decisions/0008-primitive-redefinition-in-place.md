# 0008. 프리미티브를 제자리에서 재정의한다

| 상태 | 채택 |
| --- | --- |
| 소관 | Member C (공용 계층) |

## 맥락

화면이 두 시각 언어로 갈려 있었다. shadcn/ui 기본값을 쓰는 C 화면들과, 자체 시각 규칙으로
만든 B 화면들이다. 통일 방향은 B 쪽으로 정해졌다.

## 결정

`Card`·`Button`·`Badge`·`Table` 의 **기본값 자체를** B 시각 언어로 바꾼다. variant 를 새로
다는 방식은 택하지 않았다.

## 근거

- variant 추가는 **opt-in** 이라 기존 호출부가 안 바뀐다. 두 시각 언어가 공존하고 통일이
  아니라 **계층이 하나 더 생기는 것**으로 끝난다
- DRY 가 해소되지 않는다

## 검토한 대안

- **variant 추가** — 안전하지만 통일이 아니다

## 영향

- **C 화면 7개가 한 커밋에 같이 바뀐다.** `Button` 기본값이 바뀌면 대시보드·시뮬레이터·
  온보딩 네 화면·마이페이지의 모든 버튼이 한 번에 작아지고 모서리가 바뀐다
- 그래서 **시각 회귀 베이스라인이 선행**이다. `dev/primitives` 갤러리를 P0 에서 세웠다
- 교체 PR 이 안 들어오면 공용 계층과 raw 복제본이 영구 공존한다. P4 의 eslint 규칙이 그걸
  막는 유일한 장치다
- 단계별 계획은 [UI 일관성 통일 계획](../plans/ui-unification-plan.md)
