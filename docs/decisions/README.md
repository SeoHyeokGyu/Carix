# 결정 기록 (ADR)

되돌리기 어렵거나 이미 한 번 뒤집힌 결정을 한 건씩 남긴다. **본문 문서는 결정의
*결과*를 적고, *왜 그렇게 정했는지*는 여기가 갖는다.**

## 왜 따로 두나

결정 근거가 명세 본문에 섞여 있으면 결론이 바뀔 때 본문만 고치고 근거는 남는다.
실제로 `external-api-integration.md` §3.3 이 그렇게 자기 자신과 모순됐다 — 제목과 머리
결론은 "채택하지 않음", 같은 절 아래는 "채택 완료" 였다. 기록을 따로 두면 그 상황이
**새 기록이 옛 기록을 대체(supersede)** 하는 것으로 끝난다.

## 규칙

- 파일명은 `NNNN-짧은-제목.md`. 번호는 재사용하지 않는다
- **기록은 고치지 않는다.** 결정이 바뀌면 새 번호를 만들고 옛 기록의 상태를
  `대체됨 (ADR-NNNN)` 으로 바꾼다. 본문은 그대로 둔다 — 당시 판단의 근거가 기록의 값이다
- 상태는 `채택` · `대체됨` · `폐기` 셋
- 되돌릴 수 있고 값싼 결정은 적지 않는다. 명세 본문에 한 줄로 충분하다

## 형식

```markdown
# NNNN. 제목

| 상태 | 채택 |
| --- | --- |
| 소관 | 어느 레인·문서가 이 결정을 쓰는가 |

## 맥락
무엇이 문제였나. 결정 시점에 알던 것만 적는다.

## 결정
한두 문장.

## 근거
왜 이것인가.

## 검토한 대안
무엇을 왜 접었나. 되돌릴 때 여기부터 본다.

## 영향
무엇이 이 결정에 매여 있나.
```
